# 架构决策记录

本文是已确认产品与架构决策的精简登记簿。它记录“决定及后果”，不复制任务日志、调用次数、
证据 SHA 或验收过程；这些历史事实由对应阶段实施、验收和 evidence 文件保存。修改决策必须
新增或修订 ADR，并说明兼容性、迁移和验收影响。

## ADR-001：产品定位

**状态：已接受**

QuantKing V3 是单用户、本机运行的 A 股日频研究和周度人工调仓系统。首期不做自动下单、
分钟/Tick、高频、卖空、多用户、云端或微服务。

## ADR-002：模块化单体

**状态：已接受**

采用模块化单体和外部适配器。Web 与 Worker 可作为独立 Windows 进程运行，但共享应用服务和
本地存储；不引入 Redis、Celery 或远程消息队列。外部 SDK 只能位于适配器或入口层。

## ADR-003：代码与运行数据隔离

**状态：已接受**

代码、运行数据和异盘备份分别位于 `E:\QuantKingV3`、`E:\QuantKingV3Data`、
`F:\QuantKingV3Backups`。Parquet 保存批量数据，DuckDB 查询，SQLite 保存元数据、任务和审计。

## ADR-004：多源一致性

**状态：已接受；来源角色由 ADR-021 修订**

只有两个独立来源实际持有同一主键行且在同一版本化阈值内一致，才可形成发布候选。共同缺行
不是值共识；单源行和无共识行隔离。经绑定交易日历确认的合法整范围空使用独立零行原因码。
阈值、参与来源、选源和原因进入可复算 artifact。

## ADR-005：数据范围分期

**状态：已接受**

Stage 1 只发布明确范围的沪深未复权日线；北交所、历史退市、复权和历史状态显式列为缺口，
进入研究前补足。财务、估值、行业和历史指数成分延后到 Stage 7。

## ADR-006：Qlib 定位

**状态：已接受**

Qlib 用于数据集、表达式、因子处理、训练和实验辅助；QuantKing 拥有标准数据、因子注册、标签、
股票池、切分和版本语义。Qlib 目录是带父血缘的不可变派生视图，不是主数据仓。

## ADR-007：因子、标签与模型基线

**状态：已接受**

先建设 10～20 个可人工核对因子，Alpha158 作为并行基准；主标签对齐未来 5 个交易日实际执行
区间，20 日为对照。基线模型为线性/Ridge 与 LightGBM，严格时间切分；不自动重训或切换模型。

## ADR-008：动态股票池

**状态：已接受**

每个历史日期使用当时可知的股票池，至少考虑上市时长、停牌、ST/退市整理和流动性；底层数据
全量保留，禁止用当前上市列表重写历史。

## ADR-009：双层回测

**状态：已接受**

Qlib 用于快速研究，Backtrader 用于正式事件驱动验收。两者只消费 QuantKing 组合服务输出的
同一 `TargetPortfolio`、交易规则和成本假设；正式结论以 Backtrader 口径为准。

## ADR-010：首个组合与时序

**状态：已接受**

周度调仓，模型分数 Top 30 基本等权，单股不超过 5%，保留 3% 现金缓冲；T 日收盘后生成计划，
默认 T+1 开盘执行，不使用杠杆、融资融券或卖空。

## ADR-011：交易、账户与对账

**状态：已接受**

系统不连接 QMT 或券商 SDK、不提交订单。成交与持仓只通过用户确认的文件或人工录入进入待确认
区，确认后写入策略账；首期验收一个模拟账本和一个策略。

## ADR-012：风险门与模型审批

**状态：已接受**

独立风险服务供回测、模拟和计划共用，规则分 `INFO/WARNING/BLOCK`，硬阻断不可覆盖。模型按
草稿、训练、验证、批准、使用中、停用流转，只有使用中模型能产生正式计划。

## ADR-013：Web 与后台任务

**状态：已接受**

使用 FastAPI + React + TypeScript + Vite + ECharts，只监听 `127.0.0.1`。长任务使用 SQLite
持久化队列和本地 Worker；低频事件经游标/SSE 投影，完整日志保存 JSON Lines。EOD 由用户手动
触发同一应用服务，不建设内部调度器。

## ADR-014：Python 与依赖

**状态：已接受**

统一 Python 3.12，使用 uv、`pyproject.toml` 和锁文件；供应商库与研究依赖使用明确锁定版本。

## ADR-015：日志与审计

**状态：已接受**

运行日志使用结构化 JSON Lines，SQLite 只保存低频事件、索引、摘要和业务审计。普通日志默认
保留 90 天，审计、失败验收和正式产物不自动删除。

## ADR-016：原子发布、备份与恢复

**状态：已接受**

数据、因子、模型和回测均使用临时目录、完整计算、质量检查、清单和原子发布。失败产物不可改成
成功。备份以 manifest/SHA 增量复制，不镜像删除历史，并通过真实恢复演练验收。

## ADR-017：旧项目迁移

**状态：已接受；XTQuant 日线处置由 ADR-027 修订**

旧项目不整体搬迁。候选按 `REUSE/ADAPT/REWRITE/DISCARD/DATA_ONLY` 分类，并只在目标模块所属
阶段迁移。候选分类不保证最终采纳；旧代码和文档不能覆盖本仓库权威决策。

## ADR-018：Stage 1 控制面简化

**状态：已接受**

Stage 1 只建设未复权日线所需控制面，不建设通用数据平台、来源能力矩阵、人工 `SourceOverride`
状态机或平行 evidence/checkpoint 控制面。恢复事实收敛为 Job、Raw manifest、发布 manifest 与
JSON Lines 日志；中断后建立新 Job，相同输入可复验复用。

## ADR-019：东财 IPv4 诊断策略

**状态：已退役**

历史探针曾为东财适配器采用显式 IPv4 解析以诊断 CDN/限流问题。ADR-021 已将东财移出正式来源，
该策略和证据仅作历史审计，不进入当前运行时。

## ADR-020：拒绝 FTShare

**状态：已接受**

FTShare 的 batch 合同、上游独立性、数据许可、单位、修订政策和正式发行物不足以支持生产来源，
因此不进入依赖、registry、EOD 路由或发布血缘。

## ADR-021：三角色来源路线

**状态：已接受**

正式来源固定为 BaoStock(A) 常态供数、AKShare/腾讯(B) 常态互验、AKShare/新浪(C) 异常仲裁。
A/B 每次正常采集，C 只处理异常范围；一致集合按 A、B、C 选择。东财和 FTShare 退出，
XTQuant/QMT 不计入日常路由。腾讯与新浪必须作为不同 upstream 分别记录。

## ADR-022：合法空结果样本合同

**状态：已接受**

代表性缺失场景使用经上市日期和交易日历证明的“上市前合法整范围空”，不使用无法证明的供应商
部分缺失。任何来源有行、调用失败、参考缺失或窗口跨上市日都不得归类为合法空。

## ADR-023：代表性证据链闭合

**状态：已接受**

阈值代表性验收必须绑定原始响应、调用 journal、比较行、独立参考和 composite artifact，离线
verifier 可从这些输入重算。停牌、低流动性和合法空等 objective 必须有独立来源参考，不能自证。

## ADR-024：接受冻结日线比较阈值

**状态：已接受**

协议 `comparison-thresholds.daily-bar-unadjusted.k4.v1` 接受为冻结兼容值：OHLC/`pre_close`
绝对与相对容差均为 0，volume/amount 绝对容差 50、相对容差 0。历史协议与证据保持不可变；
修改必须建立新版本和新验收证据。

## ADR-025：旧 XTQuant 只读清单

**状态：已接受；后续处置由 ADR-027 收口**

旧文件清单只作只读、封闭扫描和差异比较，不写 staging、不转换、不发布、不调用服务。扫描结果
及其冻结证据只证明可读性和候选范围，不证明数据语义或可迁移性。

## ADR-026：旧 XTQuant 受管 pilot

**状态：已接受为历史评估合同；停止执行**

pilot 以独立授权、预算、硬超时、调用 journal、先验证后写入和失败关闭评估旧文件。两次历史
attempt 均失败且未写入 staging：一次服务调用失败，一次由大规模负 OHLC/疑似复权语义触发
未复权守卫。执行器和证据保留用于审计，不构成可重放授权。

## ADR-027：拒绝旧 XTQuant 日线迁移

**状态：已接受**

旧 XTQuant 日线存在系统性、无法可靠恢复的复权语义风险，用户决定停止挽救：不再运行 pilot、
全量诊断或 full import。原文件和冻结证据不删除、不改写；`XTQUANT_LEGACY` 不进入正式 Raw、
staging、Canonical、Warehouse 或发布候选。未来重启必须作为新任务重新立项和授权。

## ADR-028：个人本地信任模型

**状态：已接受**

授权机制用于防误执行、范围漂移和意外重放，不防御本机管理员。plan/envelope/manifest 的 SHA
用于内容完整性而非身份认证；有副作用的一次性动作绑定批准内容、路径边界和 attempt ledger。
历史产物不因后续健壮性修复自动失效。本决策不降低双来源共识、质量门、发布原子性和不可覆盖要求。

## ADR-029：Stage 2 首次可用优先

**状态：已接受**

Stage 2 以尽快形成可供 Stage 3 消费的可靠研究数据为目标，不建设完整研究平台。阶段收敛为
四个任务：范围与来源资格、研究输入、股票池/主标签/10 个基础因子、Qlib 全量视图与终验。
首次正式范围必须明确且有界；未覆盖范围如实记录，不以“全 A 股”或“全部历史”代替清单。

ADR-004、ADR-021 的 A/B/C 逐行共识继续完整适用于 `daily_bar_unadjusted`。生命周期、证券状态
和复权等研究参考数据按字段冻结来源政策：交易所或法定披露等权威来源可以单独作为事实来源；
没有权威来源时，使用一个主来源并以独立日历、价格连续性或第二来源作确定性交叉检查。来源、
可用时间和修订规则必须进入版本血缘；无法确认的范围仍隔离，不得猜测或用当前状态回填历史。

首版只交付 ADR-007 允许范围内的 10 个可手算因子和周度主标签。20 日对照标签、Alpha158、
IC/分组收益/相关性完整诊断移至 Stage 3；Qlib 首版只做可删除重建的全量视图，增量构建仅在
真实资源数据证明全量构建成为瓶颈后另行立项。Stage 2 只交付一个有界研究检查页和一条关键
E2E；所有逻辑产物仍有独立版本 ID，但复用同一 manifest、Job、原子发布和校验实现，不为每类
产物建设平行控制面。旧项目文件只在确定复用时定向审计，默认直接重写简单研究逻辑。

## ADR-030：Stage 3～7 首次使用闭环

**状态：已接受**

Stage 3～5 以最快形成“候选模型 → 正式回测 → 人工调仓与对账”闭环为目标。Stage 3 只批准
可进入组合回测的候选模型，Stage 4 通过 Backtrader 正式验收后才允许把模型设为 `使用中`，
Stage 5 是首个可监督使用里程碑。模型和计划状态使用简单枚举、合法转换与审计记录表达，不建设
角色权限、通用工作流或多级审批平台。

Stage 3 的模型评价只覆盖数据/分数层指标；Top-N 收益、回撤、换手、成本和持仓集中度归入
Stage 4。Alpha158 只运行一个冻结基准，不建设参数搜索或独立生产语义。Stage 4 保留 ADR-009
双引擎要求，但只实现固定 Top 30 和首次研究窗口所需的日频 A 股规则；复杂规则采用确定性保守
拒单或简单成交上限，不建设通用撮合、组合优化或风险规则 DSL。

Stage 5 首版只支持一个规范账户快照/成交 CSV 和人工录入，精确匹配失败后交由用户确认，不建设
多券商格式、自适应解析或自动匹配引擎。Stage 6 复用既有 Job、日志、备份和恢复能力，以四个
连续历史周加速演练和一次实际人工流程验收连续运行，不要求等待四个自然周，不增加调度器或外部
告警服务。Stage 7 不属于首次使用门槛；每次只选择一个有明确消费方的数据域，完成来源资格、
版本化发布和最小消费验收，不建设通用数据平台或一次性交付全部扩展域。

后续 Web 只围绕数据研究、模型回测、调仓账户、任务运维四类用户流程增量交付；已有页面可保留
为子路由，但阶段验收不以页面数量、复杂图表或通用配置编辑器为目标。

## ADR-031：日期精度披露的保守可用时间

**状态：已接受，2026-09-10 用户确认。**

研究事实的 `available_at` 是证据支持的安全消费起点，必须保留时间精度。EXACT 保存可证明的
精确值；只有官方历史发布记录证明特定文档/修订在上海本地日期 D 公开、但没有时分秒时，
DATE 保留该日期及发布记录证据，将安全消费时点确定为下一自然日 00:00 Asia/Shanghai。
该边界不是实际披露时刻；D 日信号不能使用 DATE 事实，不推迟成下一交易日。

日期证据绑定公告标识、修订、文档 SHA 和发布记录 SHA。正文落款、URL 日期、搜索摘要或
当前采集时间单独均不能作为历史发布资格。后续修订必须有自己的公开证据，不能继承旧页面
日期以提前可用；schema 能检查绑定一致性，不能自动证明发布记录或文件字节真实。
公司行动保留精确披露时刻或已证明的发布日期之一，不用安全消费边界冒充实际披露时间。
S2-01 先实现该合同及离线边界，真实来源和正式范围仍需逐项验收；不据此授权 S2-02。
