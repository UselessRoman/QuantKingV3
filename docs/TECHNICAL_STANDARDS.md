# 技术标准与验收清单

## 1. 运行时和依赖

- Python 基线为 3.12，使用 `uv` 管理解释器、虚拟环境、依赖和锁文件。
- `pyproject.toml` 声明直接依赖，`uv.lock` 固定完整解析结果并纳入 Git。
- Qlib 使用稳定发行版；禁止依赖未固定的 Git `main` 分支。
- Node.js 只用于 React 前端开发和构建；Node 版本与前端锁文件在 Stage 0 固定。
- 新依赖必须说明用途、维护状态、许可证、Windows/Python 3.12 支持、离线影响和替代方案。
- 不因方便引入云服务、外部账号、Redis、Celery或远程数据库。

## 2. 源码结构和边界

目标结构：

```text
src/quantking/       Python 包
frontend/            React/TypeScript
tests/               Python 测试，结构与源码对应
tests/e2e/           端到端测试
configs/             无机密默认配置和 schema
scripts/             验收、迁移和维护入口
docs/                架构、规范和阶段文档
```

- 使用 `src` 布局，测试必须运行已安装包，避免从仓库根目录偶然导入。
- 模块公开接口必须有类型标注、失败语义和必要说明。
- 领域对象使用 `dataclass`、枚举或明确模型；禁止在领域边界传递无结构 `dict`。
- Web/API schema、供应商对象、数据库 ORM 对象和领域对象相互分离。
- 只在不稳定外部边界定义端口；不为简单内部函数制造无意义抽象。

## 3. 依赖隔离

以下库只能位于对应适配器或入口：

| 依赖 | 允许位置 |
|---|---|
| `xtquant`、BaoStock、AKShare、Tushare | `data/adapters` 或 `trading/adapters` |
| Qlib | `research/adapters` 或 `backtest/adapters` |
| LightGBM | `research/adapters` |
| Backtrader | `backtest/adapters` |
| FastAPI | `web` 入口和 API schema |
| SQLAlchemy、Alembic | 基础设施持久化实现 |
| DuckDB、PyArrow、Parquet 库 | 数据查询和仓储实现 |

适配器必须把第三方异常转换为稳定错误类型，并保留原始错误作为异常链或结构化日志字段。

## 4. 类型和数值语义

- 证券数量使用整数，不用浮点数。
- 行情分析允许 `float64`，必须显式处理 `NaN`、无穷和缺失。
- 资金、费用和成交账务使用 `Decimal` 或经契约确认的定点整数；不得用二进制浮点直接结算账务。
- 权重使用明确范围的十进制或浮点值，并在组合出口验证总和、现金和容差。
- 日期、交易日和时间戳是不同类型；禁止用无时区字符串混用。
- 内部时间戳存 UTC，交易日语义使用交易所本地日期。

## 5. 数据契约

- Canonical schema 是可执行契约，字段、类型、单位、主键和缺失规则均需测试。
- Raw 不可变；Canonical/Derived 每次发布新版本。
- 供应商单位在适配器/标准化层转换，转换前后均可追溯。
- 禁止返回空表伪装成功；空、无权限、网络失败和解析失败分别建模。
- 研究、回测和计划必须显式接收数据版本，不能在深层函数中选择“最新”。
- 写入临时目录后比较 manifest 与实际文件集合，再原子发布。

## 6. SQLite 和迁移

- SQLite 保存元数据、任务、配置版本、审计、策略账和对账；不存全量行情和因子矩阵。
- 使用 SQLAlchemy 2 和 Alembic；任何 schema 变化必须有升级、验证和必要的回退/恢复说明。
- 迁移前自动创建一致性备份，并在临时副本上运行迁移测试。
- 使用 WAL 和短事务；长计算在事务外执行。
- 每个 SQLite 连接设置 `busy_timeout`；Web 和 Worker 的应用写入统一经过仓储/工作单元，并对 `SQLITE_BUSY`/`SQLITE_LOCKED` 使用有界指数退避和抖动。
- 重试只允许包围可安全重放的短事务；超过上限必须显式失败，禁止吞掉锁冲突后报告成功。
- 心跳和进度合并或限频写入，完整日志行不得写入 SQLite。
- ORM 模型不得成为 API 或领域接口。

## 7. 任务和幂等

- 每个长任务有稳定 ID、输入清单、状态、心跳、日志和产物清单。
- 跨进程进度通过带单调游标的低频 `JobEvent` 持久化；SSE 是 Web 到浏览器的传输层，不是 Worker 内存事件总线。
- 相同幂等键的重复请求不得产生重复发布、重复成交或重复账务。
- 任务只在安全检查点响应取消。
- 进程崩溃后，运行中任务必须被识别为中断，不得永久悬挂。
- 上游失败或未发布时，下游任务不得启动。

## 8. 日志和审计

- 使用标准日志兼容的结构化记录，便于接入第三方库日志。
- 必须带 `event`，业务关键日志带关联 ID，异常保留堆栈。
- 日志不得包含密码、令牌、完整券商账号或任意用户隐私。
- 审计记录是业务数据，只追加；普通日志清理不得删除审计。
- 不允许捕获异常后只写日志并返回成功。

## 9. 研究和防泄漏

- 因子声明输入、窗口、复权、可用时间和处理规则。
- 标签列不能进入模型特征。
- 股票池和状态过滤使用历史时点数据。
- 所有可学习预处理仅在训练区间拟合。
- 时间切分不得随机；重叠标签设置必要隔离。
- 实验清单保存特征顺序、随机种子、库版本和代码版本。
- 从受管理目录加载模型，验证 manifest 和 SHA-256；禁止对任意用户路径执行 `pickle.load`。

## 10. 组合、回测和交易

- 组合构建是 `score → TargetPortfolio` 的唯一逻辑源。
- Qlib、Backtrader 和调仓页面使用同一组合输出。
- Qlib 正式回测使用自定义 Strategy 适配器直接消费 `TargetPortfolio`；禁止用内置组合构造策略生成第二套选股或权重逻辑。
- 回测显式接收成本、规则、数据和组合版本。
- A 股规则按生效日期版本化，不能硬编码一个常量覆盖全部历史。
- `RebalancePlan` 是意图，`BrokerSnapshot` 是总账，`Fill` 是已确认策略事实。
- QMT 接口只读；代码库不得出现调用下单/撤单接口的应用用例。

## 11. API 和 Web

- 仅绑定 `127.0.0.1`，保持同源，不启用开放 CORS。
- 路由不执行下载、训练或回测，长任务返回 `202` 和任务 ID。
- 命令端点支持幂等键和并发版本检查。
- 写操作在 UI 显示影响范围；审批、取消和覆盖操作必须审计。
- API 不接受任意文件路径、模块路径、Python 表达式或不受管理的模型文件。
- 大表分页、聚合或降采样；Web 不加载全市场完整 DataFrame。

## 12. 测试分类

### 离线自动测试

- 单元测试：纯业务规则和数值边界。
- 契约测试：所有适配器共享的输入输出约束。
- 集成测试：临时 SQLite/Parquet/DuckDB、任务、日志和迁移。
- 防泄漏测试：固定样本加性质测试；未来数据变化不得影响历史特征/股票池，标签只能读取声明窗口，推理不得加载标签。
- 双引擎校准测试：Qlib/Backtrader 的零成本基础场景和共同 A 股成本/交易约束场景。
- 并发写测试：独立进程并发执行任务心跳、进度和关键状态/审计短事务，不得丢失已提交更新或产生未处理锁错误。
- API/Web 测试：输入、状态、审批、错误和 SSE 降级。

默认测试不得访问网络、QMT、`E:\QuantKingV3Data` 或 `F:\QuantKingV3Backups`。使用 pytest 临时目录和合成数据。

### 真实环境测试

真实测试使用明确 marker，例如 `real_xtquant`、`real_backup`、`simulation_account`。必须由用户明确运行，并将外部副作用、账号和输出路径显示在命令前。

### 固定边界样本

至少包括：正常交易、停牌、涨跌停、ST、上市初期、退市、复权事件、数据缺失、部分成交、重复成交、零股和进程中断。

## 13. 质量门禁

Stage 0 固化精确命令。目标门禁至少覆盖：

```powershell
uv lock --check
uv run ruff check .
uv run ruff format --check .
uv run mypy src/quantking
uv run pytest -m "not real_xtquant and not real_backup and not simulation_account" -q -p no:cacheprovider
git diff --check
```

前端还必须运行锁文件安装、类型检查、单元测试、生产构建和关键 Playwright 流程。Markdown 链接检查必须覆盖根目录和 `docs/`。

质量门禁失败时不得更新阶段状态、发布数据/模型或合入变更。

## 14. 文档和状态

- 架构变化更新 `DECISIONS.md` 和受影响领域文档。
- 阶段开始/完成更新 `ROADMAP.md`，完成必须附实际证据。
- README 只描述当前已实现能力和明确标注的目标能力。
- 未完成能力不得使用“已支持”“可用”等措辞。
- 实施任务必须标明 Stage、范围、测试和验收结果。

## 15. 旧项目复用门槛

每个候选文件或数据集必须有审计记录，包含：

- 分类：`REUSE / ADAPT / REWRITE / DISCARD / DATA_ONLY`。
- 依赖、全局状态和外部副作用。
- 字段、单位、复权和时间语义。
- 前视、幸存者偏差和重复逻辑检查。
- 现有测试、缺失测试和新契约映射。
- 迁移后的目标模块和删除/保留计划。

没有审计记录和回归测试的旧代码不得进入 V3。
