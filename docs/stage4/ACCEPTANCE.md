# Stage 4 验收矩阵

状态：计划基线，未授权、未开始。只有全部项目通过并在 `S4-03_ACCEPTANCE.md` 记录实际证据后，
Stage 4 才能完成。

## A. 组合与风险

- [ ] 只消费已批准模型和显式 `PredictionSet`，股票池、信号日和输入版本一致。
- [ ] Top 30、基本等权、5% 单股上限、3% 现金缓冲和简单换仓/流动性规则有固定样例。
- [ ] `TargetPortfolio` 权重、现金、长仓和确定排序满足版本化容差。
- [ ] 数据/模型状态、版本一致性、非法权重和不可交易输入有稳定 `INFO/WARNING/BLOCK` 结果。
- [ ] 硬阻断不可覆盖；风险实现不依赖回测引擎或 Web。

## B. 交易规则与双引擎

- [ ] T 日信号/T+1 开盘、整手/零股、T+1 可卖、停牌、方向性涨跌停、费用和成交量上限有版本合同。
- [ ] 规则只覆盖冻结研究窗口和明确板块，未知规则会阻断而不是猜测。
- [ ] Qlib 和 Backtrader 均直接消费同一 `TargetPortfolio`、成本和共同规则决定。
- [ ] 零费用完全成交场景的持仓、方向、现金和净值在冻结容差内一致。
- [ ] 共同 A 股规则场景的成交、拒绝、现金、持仓和净值一致或有固定解释。
- [ ] 研究价、未复权成交/估值价和除权交易规则参考价区分明确，事件事实/规则版本进入血缘。
- [ ] 现金红利和送转共享手算样例通过两个引擎，股数、现金/应收权益和净值守恒，事件重复不重记。
- [ ] 已有持仓跨事件而必要事实缺失时阻断受影响回测；不能用拒新订单或空事件表掩盖执行缺口。

## C. 正式回测与启用

- [ ] Backtrader 正式回测保存输入版本、规则、目标组合、模拟订单/成交/拒绝、现金、持仓和净值。
- [ ] 报告包含收益、回撤、换手、成本、集中度、Top-N/显式基准比较和分期结果；没有指数版本时
  使用由同一股票池派生的等权基准并明确标注，不临时扩展数据域。
- [ ] 失败回测不发布、不覆盖成功结果，也不能启用模型。
- [ ] 用户只可启用已批准且正式回测通过的模型；替换/停用有审计。
- [ ] Stage 4 结束时恰有一个 `使用中` 模型，或形成明确无可用模型结论。

## D. 应用、Web 与关闭

- [ ] 回测通过现有 Job/Worker 执行；API 使用显式版本、幂等键和有界查询。
- [ ] 最小报告页可查看核心指标、净值/回撤、成本和代表性成交/拒绝，不加载全量矩阵。
- [ ] 后端、前端、双引擎校准、模型启用 E2E 和完整质量门通过。
- [ ] `S4-03_ACCEPTANCE.md` 记录正式范围、差异、限制和启用决定。
- [ ] 阶段关闭只更新为“Stage 4 完成；Stage 5 待授权”，不生成正式调仓计划。
