# S4-02 任务卡：Qlib、Backtrader 与双引擎校准

状态：未开始、未授权。

## 目标与依赖

- Stage：4。
- 依赖：S4-01 已验收。
- 目标：让 Qlib 和 Backtrader 直接执行同一 `TargetPortfolio`，证明没有第二套选股或权重逻辑。

## 范围

- Qlib 自定义 Strategy 适配器只按日期返回组合服务已生成的目标权重，不使用内置 Top-K 策略。
- Backtrader 适配器消费相同目标组合，按日频规则生成模拟订单、成交、拒绝、现金和持仓。
- 首版成交量约束使用一个冻结比例；超限采用简单部分成交或保守拒单，不建设订单簿撮合。
- 建立两个确定性校准场景：零费用/完全成交，以及共同费用/整手/停牌/涨跌停/资金约束。
- 在共同规则场景内加入 S4-01 的现金红利、送转和跨事件持仓，复用同一事件决定及独立手算预期，
  不为公司行动新增引擎各自的收益或账务算法。
- 对 Qlib 无法表达的精细规则，先验证共享规则纯函数决定，再记录引擎差异。
- 两个适配器把第三方异常转换为稳定错误，复用同一 Backtest Job 合同。

## 输出

- Qlib `TargetPortfolio` Strategy 适配器和 Backtrader 执行适配器。
- 两个固定校准 fixture、预期结果和差异报告。
- `docs/stage4/S4-02_ACCEPTANCE.md` 实际验收记录。

## 测试与验收

- 适配器代码不包含 Top 30、权重或换仓实现；更改组合规则后两个引擎同时消费新输出。
- 基础场景的目标持仓、成交方向、现金和净值在冻结容差内一致。
- 共同规则场景的订单、成交、拒绝、现金、持仓和净值一致或有明确、固定解释。
- Backtrader 覆盖 T+1、整手/零股、停牌、方向性涨跌停、费用、资金和成交量限制。
- 两个引擎的事件前后股数、现金/应收权益和净值与共享手算样例一致；除权参考价不混用研究价，
  事件重复不重复记账，必要事件事实缺失时阻止发布，不能仅拒新订单后继续报告净值。
- 失败任务保留日志且不发布 `BacktestRun`。

## 禁止项

- 不使用 Qlib 内置组合构造策略，不为引擎分别实现选股或权重。
- 不建设分钟/Tick 撮合、通用订单管理或回测参数搜索。
