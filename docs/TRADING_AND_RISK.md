# 信号、交易、对账与风险

## 权威事实

系统区分三类事实：

- `RebalancePlan`：策略打算做什么，是决策事实，不是成交事实。
- `BrokerSnapshot`：QMT 账户实际资产、持仓、委托和成交，是券商总账事实。
- 已确认 `Fill`：成交归属于哪个策略，是策略收益和成本归因事实。

任何一类都不能静默覆盖另一类。

## 信号和计划

模型分数经过组合构建和风险检查后形成目标组合，再结合策略账和账户快照生成调仓计划。

一份计划至少包含：

- 信号日期、计划执行日期和有效期。
- 数据、股票池、因子、模型、组合和交易规则版本。
- 计划前持仓、目标持仓和现金。
- 每只证券的计划方向、数量、参考价和原因。
- 预计费用、预计成交后现金和风险检查结果。
- 用户审批、取消、替代计划和审计记录。

计划生命周期：

```text
草稿 → 待确认 → 已批准 → 执行中 → 已完成
                   ├─ 部分成交
                   ├─ 已过期
                   └─ 已取消
```

批准后的计划不得原地修改。调整时取消旧计划并创建新版本，旧计划永久保留。

## QMT 边界

QMT 只读适配器允许：

- 查询资产和现金。
- 查询最新持仓。
- 查询当日委托和成交。
- 保存带抓取时间的账户快照。

不定义、不实现、不暴露任何下单、撤单或自动交易端口。若第三方 SDK 同时包含交易函数，适配器也只能包装查询接口。

## 模拟账户

开发完成后使用券商提供、QMT 可接入的独立模拟账户进行闭环。该账户不包含用户主观交易，因此券商总账与 QuantKing 策略账应可完整对齐。

数据模型仍支持多账户、多策略，避免以后把账户或策略写死。切换账户是配置和审计事件，不改变历史账务。首期实际在线闭环只运行一个模拟账户和一个策略；多账户、多策略、成交拆分及未知外部交易使用合成数据和契约测试覆盖，不作为首期在线验收门槛。

## 成交匹配与确认

```text
QMT 当日成交
    → 去重并保存原始成交
    → 按账户、证券、方向、日期、数量和价格匹配计划
    → 生成待确认建议
    → 用户批量或逐笔确认
    → 写入 Fill 和策略归属
```

- QMT 原始成交必须通过稳定成交标识或复合键幂等导入。
- 一笔计划允许多笔部分成交；一笔成交在需要时允许明确拆分归属。
- 自动匹配只能给出建议，不能直接写入策略账。
- 未匹配成交必须分类为待处理、其他策略或外部交易，并保留原因。
- 每笔原始成交保存价格、数量、费用、时间和券商标识，不只保存汇总均价。

## 策略账与对账

策略账由已确认成交、现金流和费用推导。对账至少比较：

- 各策略虚拟持仓之和与券商总持仓。
- 策略现金加未分配现金与券商可用/总现金。
- 当日计划、委托、成交和策略登记。
- 证券数量、成本、费用和无法归属的差异。

差异状态至少为 `OPEN / EXPLAINED / RESOLVED`。修正通过追加调整或撤销错误归属完成，不能修改原始券商成交。

## 风险门禁

风险服务在回测、模拟账户和未来实盘计划中复用同一规则接口：

```text
数据和模型状态
    + 目标组合
    + 策略账
    + BrokerSnapshot
    + 交易规则版本
    → RiskAssessment
```

### 风险类别

1. 数据：新鲜度、质量、备用源使用和输入版本一致性。
2. 模型：审批状态、有效期、因子覆盖和近期表现衰减。
3. 组合：持仓数、单股权重、现金、换手、流动性和集中度。
4. 成交：可用资金/股份、T+1、整手、停牌、涨跌停和费用。
5. 账户：快照新鲜度、未知持仓、未确认成交和未关闭差异。
6. 运行：上游任务、产物清单、失败状态和版本血缘。

### 级别

- `INFO`：记录，不影响审批。
- `WARNING`：明确展示；允许继续时必须符合覆盖规则。
- `BLOCK`：禁止批准计划。

有限人工覆盖必须记录操作者、时间、原因、旧值、新值和关联计划。前视数据、资金不足、非法数量、模型未批准、输入版本不一致等硬阻断不能覆盖。

## A 股交易规则版本

交易规则必须按交易所、证券板块和生效日期版本化，至少描述：

- 买入申报数量和零股卖出。
- 价格最小变动单位。
- 涨跌幅比例、无涨跌幅阶段和风险警示规则。
- 停牌和交易状态。
- 买入后可卖时间。
- 税费及其生效日期。

不得把当前规则硬编码后回填全部历史。规则变化应产生新版本，并配有生效日前后的测试样本。

规则版本表是人工策展产物，不假设能够从行情接口自动获得。每条规则至少保存官方交易所、监管/税务机关或券商材料的来源、发布日期、生效日、适用范围、原始证据位置、解释说明和维护记录。券商账户佣金方案与市场通用规则分开版本化；来源无法确认的规则不得进入正式回测或计划。

## 模拟验收

考虑接入真实账户前，模拟账户至少运行一个完整月度周期且完成不少于 4 次周度调仓，并满足：

- 数据、因子、预测、风险和计划按预定顺序运行。
- 4 次计划均完成审批、人工下单、同步、确认和对账。
- 不存在无法解释的持仓或资金差异。
- 程序重启后任务、计划和账务可恢复。
- 部分成交、未成交、停牌和涨跌停已通过模拟或专项测试。
- 所有 `BLOCK` 规则有自动测试。
- 形成独立验收报告，由用户决定是否进入真实账户准备。

模拟通过不自动授权真实账户，也不改变“禁止自动下单”的产品边界。
