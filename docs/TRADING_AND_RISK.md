# 信号、人工调仓、对账与风险

## 边界

QuantKing 生成目标组合和人工调仓计划，不连接 QMT 或其他券商 SDK，不提交或撤销订单，也不保存券商账号密码。用户在自己的券商客户端完成交易。

系统区分：

- `RebalancePlan`：策略计划；
- `ImportedBrokerRecord`：用户确认导入的成交、持仓或现金记录；
- `Fill`：已经确认归属于某策略的成交。

三者不能互相覆盖。

## 计划

计划至少绑定信号日、执行日、数据/模型/规则版本、计划前持仓、目标持仓、现金、数量、参考价、费用和风险结果。批准后不可原地修改；调整时创建新版本。

```text
草稿 → 待确认 → 已批准 → 已完成
  └──────────────→ 已取消
```

首版状态只用简单枚举、合法转换和审计记录表达，不建设工作流引擎。部分成交和过期是计划结果/
关闭原因，不扩张为需要独立服务编排的状态机。

## 成交与持仓导入

Stage 5 首版只支持用户主动提供的一种规范 CSV 或人工录入：

1. 文件 schema 和单个账户标识显式选择；
2. 原始文件或摘要只追加保存；
3. 通过稳定成交 ID 或复合键幂等；
4. 只做确定性精确匹配，匹配结果仅生成待确认建议；
5. 用户确认后才写策略账；
6. 未匹配记录保持待处理并显示原因。

不建设 JSON/多券商自适应解析、模糊自动匹配、浏览券商客户端、读取本机密码、自动登录或 SDK
同步。Stage 5 任务见 [Stage 5](stage5/README.md)。

S5-02 在同一待确认流程中增加最小人工现金红利/送转调整，复用 Stage 4 事件规则，记录来源、
事件键、生效时点、现金/应收权益/股数变化与用户确认。确认后只追加入账，重复导入/确认不重记；
非成交调整不伪造 `Fill`，账户快照不覆盖策略账。必要事件事实未知时保留差异并阻断依赖该账务的
计划批准，不建设通用公司行动平台或新增券商格式。

## 风险门禁

风险服务分阶段复用同一纯函数入口：Stage 4 检查数据/模型状态、目标组合和交易规则；Stage 5
再加入策略账和导入账户快照。不建设风险规则 DSL 或独立风险平台。

- `INFO`：记录。
- `WARNING`：展示；允许覆盖时必须填写原因。
- `BLOCK`：禁止批准。

前视数据、输入版本不一致、资金不足、非法数量和模型未批准属于不可覆盖阻断。

## A 股交易规则

整手、T+1、停牌、涨跌停、费用和板块差异按生效日期版本化。市场规则与个人券商佣金分开；来源无法确认的规则不得进入正式回测或计划。

## 模拟验收

Stage 5 先关闭一次完整模拟调仓并达到首次可监督使用。Stage 6 使用四个连续历史交易周加速回放，
覆盖部分成交、重复导入和程序重启，不等待四个现实自然周；任务见 [Stage 6](stage6/README.md)。
模拟通过不授权自动交易，也不会引入券商 SDK。
