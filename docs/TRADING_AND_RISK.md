# 信号、人工调仓、对账与风险

## 边界

QuantKing 生成目标组合和人工调仓计划，不连接 QMT 或其他券商 SDK，不提交或撤销订单，也不保存券商账号密码。用户在自己的券商客户端完成交易。

系统区分：

- `RebalancePlan`：策略计划；
- `ImportedBrokerRecord`：用户确认导入的成交、持仓或现金记录；
- `Fill`：已经确认归属于某策略的成交。

三者不能互相覆盖。

## 计划

计划至少绑定信号日、执行日、数据/模型/规则版本、计划前持仓、目标持仓、现金、数量、参考价、费用和风险结果。批准后不可原地修改；调整时创建新版本。

```text
草稿 → 待确认 → 已批准 → 执行中 → 已完成
                   ├─ 部分成交
                   ├─ 已过期
                   └─ 已取消
```

## 成交与持仓导入

未来只支持用户主动提供的 CSV/JSON 或人工录入：

1. 文件 schema 和账户标识显式选择；
2. 原始文件或摘要只追加保存；
3. 通过稳定成交 ID 或复合键幂等；
4. 自动匹配只生成待确认建议；
5. 用户确认后才写策略账；
6. 未匹配记录保持待处理并显示原因。

不建设浏览券商客户端、读取本机密码、自动登录或 SDK 同步。

## 风险门禁

风险服务统一检查数据/模型状态、目标组合、策略账、导入的账户快照和交易规则版本。

- `INFO`：记录。
- `WARNING`：展示；允许覆盖时必须填写原因。
- `BLOCK`：禁止批准。

前视数据、输入版本不一致、资金不足、非法数量和模型未批准属于不可覆盖阻断。

## A 股交易规则

整手、T+1、停牌、涨跌停、费用和板块差异按生效日期版本化。市场规则与个人券商佣金分开；来源无法确认的规则不得进入正式回测或计划。

## 模拟验收

首期使用本地模拟账本和人工成交记录完成至少 4 次周度调仓。要求计划、成交确认、策略账和差异均可解释，程序重启可恢复。模拟通过不授权自动交易，也不会引入券商 SDK。
