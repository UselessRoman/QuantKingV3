# Stage 0 S0-06 旧项目只读迁移清单说明

状态：S0-06 与 S0-07 只读清单复核已通过。本说明与生成的证据仍只是候选审计，不表示任何旧代码、数据或模型已经迁移。

## 安全边界

- 输入固定为旧项目文件系统；遍历使用原生目录递归，不依赖 Git 可见性。
- 不跟随符号链接、junction 或其他 Windows reparse point；不可读项使用稳定原因码记录。
- 不导入、执行、格式化、复制或修改旧项目，也不启动旧程序、QMT、网络或外部服务。
- 配置、数据库、数据、模型、日志、失败/备份和二进制只读取文件系统元数据，不读取内容。
- 默认关闭内容哈希，正式清单只读取文件系统元数据；仅在合成测试或另行确认安全内容后，才可用
  `--hash-small-code` 对不超过 1 MiB 的非敏感代码文本计算可选 SHA-256。报告没有内容预览字段。
- 相对路径中的长数字或十六进制标识会脱敏；异常消息不写入报告。
- 代码、配置和文档逐项记录；同质数据及二进制产物按稳定目录前缀和扩展名分组。
- 所有数据候选只能标记为 `DATA_ONLY`，且仍须在 Stage 1 完成 schema、血缘、时点和质量验证。
- 旧业务实现不得直接标记为 `REUSE`；工具/测试意图最多标记为 `ADAPT`，其余代码保守标记为 `REWRITE`。

## 执行顺序

先执行只生成内存统计和控制台摘要的 dry-run：

```powershell
. .\scripts\activate-toolchain.ps1
python .\scripts\inventory_legacy.py --root E:\QuantKing --dry-run
```

确认参数和边界后，正式证据只写入 V3 仓库：

```powershell
python .\scripts\inventory_legacy.py --root E:\QuantKing
```

默认输出：

- `docs/stage0/evidence/legacy_inventory.json`：机器可读、稳定排序的完整分类字段和守恒汇总。
- `docs/stage0/evidence/legacy_inventory.md`：审查友好的覆盖、分类、候选项和跳过项报告。

工具在清单扫描前后分别计算 `相对路径 + 类型 + 大小 + mtime_ns` 的稳定 SHA-256 集合指纹；
两次指纹不同会阻止写报告。输出路径必须位于 V3 仓库且不得位于旧项目源目录。

## 分类解释

| 分类 | S0-06 含义 |
|---|---|
| `REUSE` | 只有契约和测试充分时才可能采用；本次元数据审计不会授予该结论。 |
| `ADAPT` | 只保留意图，目标 Stage 必须按 V3 边界重做并补齐测试。 |
| `REWRITE` | 保留需求或线索，不复用旧实现。 |
| `DISCARD` | 不迁移；必要时只在原旧项目中保留为历史证据。 |
| `DATA_ONLY` | 仅作为后续数据校验候选，未校验、未复制、未迁移。 |

分类规则只依据路径和文件系统元数据，因此无法证明代码行为、数据口径、测试有效性、依赖兼容性
或无前视性。对应目标 Stage 必须重新检查这些语义。
