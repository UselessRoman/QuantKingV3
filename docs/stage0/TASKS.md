# Stage 0 任务卡

所有任务均属于 Stage 0，并受 [Stage 0 总合同](README.md) 约束。每个实现任务必须测试先行，且不得开始依赖尚未验收的任务。

## S0-01：工程、锁定环境与公共契约

### 依赖与输入

- 依赖：本目录合同已经确认；无代码前置。
- 输入：架构决策、技术标准、目标源码结构和本机基线审计。
- 外部授权：下载/安装稳定 Python 3.12、`uv`、Node.js，以及解析 PyPI/npm 锁文件前必须取得明确授权。

### 范围

- 初始化有效 Git 仓库；固定主分支和文本/忽略规则。
- 固定稳定版 Python 3.12、`uv`、Node.js LTS、`pyproject.toml`、`uv.lock`、前端包管理器和锁文件。
- 使用 `src/quantking` 布局建立架构规定的模块空壳；测试必须导入已安装包。
- 建立统一错误、ID、UTC 时间/交易日、配置和受管理路径契约。
- 本机配置和机密不入 Git；路径校验不在导入时创建运行目录。
- 固定 Ruff、mypy、pytest marker、前端类型/单测/构建、Playwright 和 Markdown/架构边界检查入口。
- 记录所有直接依赖的用途、维护状态、许可证、Windows/Python 3.12 支持、离线影响和替代方案。

### 测试先行

- 先为错误转换、ID 格式、UTC 拒绝无时区值、交易日区分、配置优先级、绝对路径/越界/重叠路径写失败测试。
- 先为包必须从安装路径导入、禁止层级导入和 Markdown 链接检查写失败检查。
- 锁文件必须能用 frozen/check 模式验证，不以当前全局环境冒充可复现环境。

### 禁止项

- 不实现任务队列、数据库模型、Web API、备份或业务对象。
- 不把现有 Python 3.10 或 Python 3.12 预发布版作为通过证据。
- 不引入 Redis、Celery、远程数据库、云服务或业务依赖。

### 输出与验收

- 工程配置、Python 包空壳、公共契约、测试、质量脚本和依赖决策记录。
- `uv lock --check`、frozen 同步、Ruff、格式、mypy、离线 pytest 和边界检查通过。
- 前端锁文件可重复安装，最小脚本能运行；完整页面在 S0-04 交付。

## S0-02：联合兼容性与 Qlib 合成目标权重探针

### 依赖与输入

- 依赖：S0-01 已验收。
- 输入：锁定解释器/依赖、Qlib 支持的自定义 Strategy 接口、合成目标权重。
- 外部授权：首次下载依赖沿用该次明确批准；真实 XTQuant 读取或 QMT 连接需要对应任务的明确授权。

### 范围

- 在同一稳定 Python 3.12 锁定环境验证 XTQuant、Qlib、LightGBM、Backtrader、DuckDB、SQLite 和 FastAPI。
- 探针至少记录解释器、平台、包版本、执行步骤、结果和稳定失败语义。
- 使用小型合成数据分别执行 DuckDB 查询、SQLite WAL 读写、LightGBM 训练/预测、Backtrader 空业务冒烟和 FastAPI 测试客户端健康检查。
- 为锁定 Qlib 版本实现只属于探针的自定义 Strategy：按日期直接消费预先生成的合成目标权重；记录 Stage 4 应采用的稳定扩展点。
- 证明探针没有使用 Qlib 内置组合构造策略重新选股或计算权重。
- XTQuant 探针只验证 Python 3.12 下的最小只读能力，不下载完整行情，不访问账户，不包装交易函数。

### 测试先行

- 先写版本缺失、接口漂移、目标权重日期缺失、非法权重和第三方异常转换测试。
- 合成分数的任意变化不得改变预置目标权重输出；测试禁止出现 `TopkDropoutStrategy` 等内置组合构造器。
- 默认离线测试不得隐式跳过必须安装的锁定依赖；真实 XTQuant 用明确 marker 隔离。

### 禁止项

- 不实现 Stage 2 研究数据、Stage 4 组合服务或正式回测。
- 不把 import 成功单独当作全部联合兼容性通过。
- 不连接账户，不下载历史行情，不调用下单/撤单 API。

### 输出与验收

- 可重复探针、合成夹具、离线测试、真实 XTQuant marker 和兼容性报告。
- 锁定环境中的离线联合探针全部通过；经授权的 XTQuant 最小只读探针通过。
- 报告明确记录 Qlib 扩展点、选择依据和 Stage 4 边界。

## S0-03：SQLite、迁移、持久任务、日志与并发

### 依赖与输入

- 依赖：S0-01 已验收；不得依赖 S0-04 页面。
- 输入：公共 ID/时间/配置/路径/错误契约和 Web 运维文档中的任务语义。
- 外部授权：无；全部测试使用 pytest 临时目录和合成通用任务/审计数据。

### 范围

- 建立 SQLAlchemy 2、Alembic 初始迁移和临时数据库升级验证。
- 每个 SQLite 连接启用 WAL、外键、`busy_timeout`；使用短事务。
- 对安全可重放短事务实现有界指数退避和抖动；超过上限显式失败。
- 实现通用 `JobRun`、单调 `JobEvent`、幂等键、心跳、协作取消、成功/失败/中断状态和 Worker 注册表骨架。
- 状态变更与对应事件在同一事务提交；游标查询为有界批次。
- 进程恢复把遗留 `RUNNING` 标为 `INTERRUPTED`；上游失败不得返回成功。
- 实现标准日志兼容的 JSON Lines 运行/任务日志，带 `event`、UTC 时间、关联 ID、异常链和敏感字段掩码；完整日志不写入 SQLite。
- 实现只追加的通用审计记录；不得提前实现策略账。

### 固定并发门

- Windows `spawn` 启动 4 个独立进程。
- 每个进程提交 25 次通用心跳、进度或审计短事务，共 100 次。
- 单次测试硬上限 30 秒。
- 必须证明：无已提交更新丢失、无未处理 `SQLITE_BUSY/SQLITE_LOCKED`、无吞错报成功、无无限等待；事件游标严格单调且关键状态一致。
- `busy_timeout`、最大重试次数、退避基数/上限和抖动范围由红测和实测在本任务固化，并写入配置与文档。

### 测试先行

- 先写迁移、状态机非法转换、幂等、原子事件、游标恢复、崩溃恢复、日志 schema/掩码和上述多进程失败测试。
- 通过显式锁持有夹具证明达到重试上限后失败，而不是无限等待。

### 禁止项

- 不实现数据抓取、训练、回测、策略账或 QMT 任务。
- 不用线程测试代替固定多进程门，不把每条日志复制到 SQLite。
- 不捕获异常后只记录日志并返回成功。

### 输出与验收

- ORM 与领域对象分离的持久化实现、Alembic 迁移、Worker 骨架、JSONL 日志和完整离线测试。
- 临时数据库从空库迁移并验证；固定并发门在 30 秒内通过。

## S0-04：FastAPI、SSE、React/Vite 与 Playwright

### 依赖与输入

- 依赖：S0-01、S0-03 已验收。
- 输入：任务仓储、`JobEvent` 游标、JSONL 受控读取接口和 Web 边界。
- 外部授权：npm 依赖首次下载需明确授权；默认测试不访问外网或运行数据根目录。

### 范围

- 实现 FastAPI 应用工厂、健康检查、任务状态/有界事件查询、最小 SSE 和同源静态前端托管。
- SSE 支持 `Last-Event-ID` 或等价游标恢复；REST 状态/事件轮询作为降级路径。
- 路由只做 schema、用例调用和映射，不直接访问 SQLite、日志文件或业务 SDK。
- 启动入口只绑定 `127.0.0.1`，不启用开放 CORS。
- 建立中文 React + TypeScript + Vite 最小壳，只显示健康状态、任务状态和可恢复事件流，不实现业务页面。
- 固定前端类型检查、单元测试、生产构建和关键 Playwright 冒烟。

### 测试先行

- 先写健康响应、错误 schema、游标边界、SSE 重连/去重/顺序、静态回退和绑定地址检查。
- 前端先写健康/失败/断线恢复状态测试；Playwright 验证页面加载、健康状态和事件恢复的关键流程。

### 禁止项

- 不实现数据、因子、模型、回测、调仓或账户页面。
- 不让路由执行长任务，不把 SSE 做成进程内 Worker 总线。
- API 不接受任意文件路径、模块路径或 Python 表达式。

### 输出与验收

- 后端/API 测试、前端源码/锁文件/单测/构建、关键 Playwright 流程全部通过。
- 生产构建由 FastAPI 同源提供，启动配置只监听回环地址。

## S0-05：本地/异盘备份、增量复制与恢复

### 依赖与输入

- 依赖：S0-01 已验收；数据库备份可与 S0-03 协作但不得绕过其连接契约。
- 输入：人工合成运行根、SQLite WAL 数据库、配置、清单和分区对象。
- 外部授权：离线实现只用临时目录；写 `E:\QuantKingV3Data` 或 `F:\QuantKingV3Backups`、真实恢复演练均需本任务明确授权，每次失败后的重试重新授权。

### 范围

- 实现一致性 SQLite 在线备份，不复制正在写入的单个主文件冒充成功。
- 每个恢复点包含输入清单、逐文件大小/SHA-256、代码与数据库版本、完成标记和结构化失败信息。
- 使用临时目录完成复制、集合一致性与校验后原子发布；失败目录永不改成成功。
- 使用源 manifest/SHA-256 只复制目标端缺失或变化的分区对象，并报告 copied/skipped/conflicted。
- 复制逻辑不得使用镜像删除；保留清理是独立、显式、可审计且不在本任务执行的策略。
- 恢复到新的隔离目录，验证实际文件集合、校验和、SQLite `quick_check`/schema 和完成标记后才标为已验证。
- Stage 0 实测并记录 Windows/F 盘工具、频率、保留期、访问控制和恢复步骤；不弱化清单语义去迎合工具。

### 测试先行

- 先写 WAL 活跃备份、源变更、校验和冲突、空间不足、路径越界、增量跳过、历史恢复点保留、失败目录保留和恢复校验失败测试。
- 已完成快照的 SQLite 验证必须只读且不得产生 `-wal/-shm` 副产物。

### 禁止项

- 不使用 `shutil.copy/copy2` 直接复制活跃 SQLite 主文件。
- 不修改、删除、复用失败目录；不通过把额外文件加入 manifest 来掩盖集合差异。
- 不读取或备份真实用户数据，除非命令前已获对应明确授权。

### 输出与验收

- 离线合成备份/增量/恢复测试全部通过。
- 经授权后，本地与 F 盘都从人工测试数据恢复并验证清单、校验和、完成标记和增量分区复制；证据路径固定且可复查。

## S0-06：旧项目只读迁移清单

### 依赖与输入

- 依赖：S0-01 已验收；可与 S0-02～S0-05 独立实施。
- 输入：`E:\QuantKing` 文件系统、旧项目 Git 元数据和新架构目标模块。
- 外部授权：只读审计已在用户指定范围内；不得写旧项目、启动旧程序或访问其外部服务。

### 范围

- 使用文件系统清单覆盖旧项目的代码、配置、文档、数据库、数据、模型、日志和失败/备份产物；不得只依赖会受 `.gitignore` 影响的 `git ls-files` 或 `rg --files`。
- 对敏感配置、数据库和二进制数据只记录必要元数据、相对路径、大小、类型、可选校验和与分类，不输出机密或读取业务内容。
- 每个候选文件或同质数据集合分类为 `REUSE / ADAPT / REWRITE / DISCARD / DATA_ONLY`，并记录依据、依赖/全局状态/外部副作用、语义风险、现有/缺失测试、目标 Stage/模块和后续处置。
- 明确所有分类只是候选审计；实际迁移只能在目标模块所属 Stage 进行。
- 用稳定排序和汇总校验证明清单覆盖范围，并记录不可读项/跳过原因。

### 测试先行

- 先用合成目录测试 Git 忽略文件、二进制/敏感文件、不可读项、目录级分类、稳定排序和汇总计数。
- 对旧项目执行前先 dry-run；执行后证明旧项目文件时间/内容未被修改。

### 禁止项

- 不复制、导入、格式化、运行或修改旧项目内容。
- 不把整个目录统一标为 `REUSE`，不把未校验数据标为已迁移。
- 不在报告中泄露密码、令牌、完整账号或敏感配置值。

### 输出与验收

- 生成可审查的只读迁移清单、分类报告、覆盖汇总和工具测试。
- 清单覆盖旧项目代码、数据和模型，旧项目保持未修改。

### 范围

- 任一门禁失败即停止完成状态更新；保留日志和失败产物。

- 外部失败重试使用新输出路径并重新取得授权。

### 输出与验收

- 完整、可复查的 Stage 0 验收报告和全部命令证据。
- [验收矩阵](ACCEPTANCE.md) 无缺口；README/路线图准确写明 Stage 0 完成、Stage 1 未开始。
