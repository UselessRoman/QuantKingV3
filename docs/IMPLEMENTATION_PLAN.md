# QuantKing V3 实施计划

## 当前状态

设计阶段已完成并获得用户确认。Stage 0 已于 2026-07-16 完成验收，证据见 [Stage 0 最终验收报告](stage0/FINAL_ACCEPTANCE.md)；Stage 1 已获实施授权并进行中，但尚未完成。任何阶段状态只能在完成条件有实际证据后更新。

## 执行规则

1. Stage 按顺序实施，前一阶段未完成不得开始下一阶段。
2. 每个任务必须注明所属 Stage、范围、输入、测试和验收证据。
3. 每个 Stage 纵向交付领域逻辑、持久化、API、Web、日志和测试。
4. 真实网络、正式数据根和 F 盘备份测试需要明确授权。
5. 失败产物原样保留；修复通过新任务完成，不修改失败结果。
6. 旧项目迁移只在目标模块所属阶段进行，不设整体复制阶段。

## Stage 0：工程与可恢复基线

### 目标

建立可重复、可检查、可恢复的工程基础，不实现业务主链路。

### 范围

- 初始化 Git、Python 3.12、`uv`、`pyproject.toml`、锁文件和 `src` 布局。
- 验证 XTQuant、Qlib、LightGBM、Backtrader、DuckDB、SQLite 和 FastAPI 的联合兼容性。
- 用合成目标权重探针验证锁定 Qlib 版本的自定义 Strategy 扩展点，并记录 Stage 4 采用 `WeightStrategyBase`、`BaseStrategy` 或等价稳定接口；不在 Stage 0 实现选股或组合业务逻辑。
- 固定 Node.js、React、TypeScript、Vite 和前端锁文件。
- 建立模块空壳、统一错误、配置、ID、时间和路径契约。
- 建立 SQLAlchemy/Alembic、SQLite WAL 和临时数据库迁移测试。
- 建立持久化任务模型、Worker 骨架、结构化日志、SQLite `JobEvent` 游标和最小 SSE。
- 固化 SQLite `busy_timeout`、有界退避、心跳限频和跨进程并发写测试；只使用通用任务/审计测试数据，不提前实现策略账。
- 建立最小 Web 壳与健康检查，不实现业务页面。
- 实现本地快照与 F 盘备份的一致性备份、清单、验证和恢复演练；实测并固定 Windows/F 盘工具，验证按 manifest/SHA-256 只复制缺失或变化分区，且复制过程不镜像删除既有恢复点或失败产物。
- 固化 Ruff、mypy、pytest、前端测试、Playwright 冒烟和 Markdown 链接门禁。
- 对 `E:\QuantKing` 生成只读迁移清单和 `REUSE/ADAPT/REWRITE/DISCARD/DATA_ONLY` 分类；不迁移代码。

### 禁止事项

- 不接入完整历史行情。
- 不计算因子、训练模型或实现回测策略。
- 不连接真实或模拟交易账户。
- 不从旧项目复制业务目录。

### 完成条件

- 全新机器/干净环境可通过锁文件安装并运行质量门禁。
- XTQuant 和 Qlib 在 Python 3.12 的最小只读探针通过。
- 锁定的 Qlib 版本可通过受支持的自定义 Strategy 接口消费合成目标权重，且未调用内置组合构造策略。
- Web、Worker、SQLite、JSON Lines 日志、`JobEvent` 游标恢复和任务状态有可重复的离线集成测试。
- 多进程并发写心跳、进度和关键状态/审计时，无丢失更新、未处理锁错误或无限等待；具体负载和时间上限在 Stage 0 任务卡中固化。
- 本地和 F 盘备份均能从人工测试数据恢复，并验证清单、校验和、完成标记及增量分区复制；保留清理与备份复制相互独立。
- 迁移清单覆盖旧项目代码、数据和模型，不修改旧项目。
- README/路线图准确记录 Stage 0 完成、Stage 1 未开始。

### 验收结论

2026-07-16，S0-01～S0-07 的验收矩阵全部通过。锁定环境、XTQuant/Qlib 兼容性、SQLite 多进程门、Worker/JSON Lines/SSE、真实本机 Edge、两次经授权的本地/F 盘合成恢复演练和旧项目只读清单均有可复查证据。Stage 0 完成；Stage 1 已获实施授权并进行中，但尚未完成。

- 数据质量失败会阻止发布，并以脱敏错误链、受影响计数和有界行级证据在 Web 显示；数据中心

- 旧 XTQuant 候选处置有可复验的冻结结论：本项目为 ADR-027 拒绝迁移（inventory 成功、
  两次 pilot 失败证据与诊断冻结、旧根未修改）；受管导入框架的"可中断重跑、按内容幂等、
  未复核数据不发布"由离线合成回归证明，且 `XTQUANT_LEGACY` 不进入发布链。

## Stage 2：Qlib 数据、因子与标签

### 目标

以显式发布的 Stage 1 日线版本为父输入，先补足 point-in-time 复权与历史状态，再建立可人工
核对、无前视和可复现的股票池、标签、基础因子和 Qlib 派生视图。Stage 2 只交付可靠研究
输入，不训练模型、不构建组合或运行正式回测。

详细合同、任务所有权和验收项见 [Stage 2 当前入口](stage2/README.md)、
[任务卡](stage2/TASKS.md)与[验收矩阵](stage2/ACCEPTANCE.md)。本路径已规划但未开始；只有
S1-08R3 完成 Stage 1 最终验收后才能启动 S2-01。

### 实施顺序

1. **S2-01 研究合同与固定样本**：冻结正式研究范围、复权/历史状态、周度与 20 日标签、
   流动性和不可成交语义；只定向审计旧 Qlib/因子候选。
2. **S2-02 point-in-time 研究输入**：先验证父日线覆盖，必要时只复用 Stage 1 管线发布包含
   历史退市证券的覆盖扩展新版本；再补足生命周期、逐日状态和复权因子，发布
   `ResearchInputVersion` 和 DataCenter 覆盖/缺口视图。
3. **S2-03 股票池与标签**：发布带逐日排除原因的 `UniverseVersion` 和执行对齐
   `LabelVersion`，交付有界样本检查 API/Web。
4. **S2-04 基础审计因子**：注册并发布 15 个简单量价因子，先交付定义、覆盖、缺失和分布页。
5. **S2-05 Qlib 与研究诊断**：导出不可变 Qlib 派生视图，接入 Alpha158 基准，补齐 IC、
   分组收益和相关性；增量构建必须与全量重建校准。
6. **S2-06 正式构建与终验**：在明确证券/日期范围内完成正式研究链、内容幂等、独立只读
   复验、Web E2E 和完整门禁；通过后仍须另行授权 Stage 3。

### 范围

- 除复用 Stage 1 日线合同进行必要的历史覆盖扩展外，只补充研究必需的证券生命周期、逐日
  状态和逐日复权因子，不建设通用证券主数据平台或第二条行情管线。
- 在研究层保留未复权事实并派生追加稳定、可追溯的连续研究价格；不得修改 Stage 1 Warehouse。
- 实现逐日动态股票池与明确排除原因，历史退市证券和状态不得由当前列表回填。
- 用版本化交易日历样例固化执行对齐的周度主标签和未来 20 日对照标签，包括 T+1 执行参考
  价、下一调仓执行参考价及日线可证明的不可成交语义。
- 建立最小因子注册与版本血缘，完成 15 个基础审计因子和确定性手算样本；训练期预处理留给
  Stage 3，不提前建设通用特征平台。
- 从明确研究版本导出可重建 Qlib 视图；兼容追加可在新临时目录增量导出，其他变化全量重建，
  且不得修改已发布 Qlib 目录。
- 接入 Alpha158 基准集并记录与基础审计因子的语义差异；它不能绕过注册和版本入口。
- 分步交付研究输入覆盖、状态/标签样本、因子覆盖/分布、IC、分组收益和相关性 API/Web。
- 旧项目只定向审计已登记的 Qlib 转换和因子文件；不整体读取或复制，模型候选留给 Stage 3。

### 完成条件

- 给定父数据、状态、股票池、标签和因子版本可重复生成同一业务内容摘要和清单。
- point-in-time 复权、生命周期与逐日状态有真实代表样本和逐证券覆盖证据；当前状态不能回填
  历史，未来公司行动或状态扰动不改变生效前结果。
- 标签、滚动窗口和截面处理有固定样本与性质防泄漏测试；未来数据扰动不改变历史特征/股票池，
  标签不越过声明窗口，推理不加载标签。
- 增量 Qlib 导出有清单校验，并能通过固定样本或周期性任务与全量重建结果校准；不一致时回退全量构建。
- 15 个基础因子均有人工可核对样本；Alpha158 不能绕过注册表。
- 研究输入、股票池/标签和因子页面均只读显式版本并通过后端、前端和关键 E2E 验收。

## Stage 3：模型实验与审批

### 目标

完成线性/Ridge 与 LightGBM 的可复现实验和模型生命周期。

### 范围

- 实现时间切分、滚动/走步验证和训练期预处理。
- 建立线性/Ridge 与 LightGBM 实验模板。
- 保存实验参数、特征顺序、随机种子、库版本、模型、预测和校验和。
- 输出 IC、Rank IC、ICIR、分期稳定性和特征重要性。
- 实现模型草稿、训练、验证、批准、启用和停用。
- 实现每月模型健康复核、有效期/衰减告警和人工触发重训；不实现自动重训或自动切换。
- 模型实验页面支持比较、审批和审计。

### 完成条件

- 相同输入与种子产生可接受容差内的相同结果。
- 训练、验证、测试及标签隔离测试通过。
- LightGBM 与线性/Ridge 基线有统一报告，不能只报告最优模型。
- 只有使用中模型可以生成正式预测集。
- 衰减或过期告警不会自动创建实验、重训或替换使用中模型。

## Stage 4：组合、风险与双层回测

### 目标

将模型分数转换为统一目标组合，并通过 Qlib 和 Backtrader 验证。

### 范围

- 实现 `PredictionSet → TargetPortfolio` 唯一组合服务。
- 固化周度 Top 30、基本等权、5% 上限、3% 现金和换仓缓冲。
- 建立独立风险门禁与 `INFO/WARNING/BLOCK`。
- 建立按日期版本化的 A 股交易规则和成本模型。
- 建立人工策展的交易规则来源目录，区分市场规则与账户佣金，并为生效日前后建立固定测试样本。
- 实现直接消费 `TargetPortfolio` 的 QuantKing Qlib Strategy 适配器和快速研究回测；禁止内置组合构造策略参与正式校准。
- 实现 Backtrader 正式回测、订单、拒绝、费用、现金和持仓。
- 建立零成本基础校准、共同 A 股成本/交易约束校准和成本/流动性压力测试。
- 回测中心展示输入版本、净值、回撤、成交和差异。

### 完成条件

- 两个引擎消费同一目标组合，不复制选股逻辑。
- 零成本基础场景及两个引擎共同支持的真实费用、整手、停牌和方向性涨跌停场景达到固定容差或差异有测试说明。
- 正式回测覆盖 T+1、整手、停牌、涨跌停、费用和部分成交。
- 正式使用的交易规则均有来源、生效日期、适用范围和生效日前后测试证据。
- 回测结果可追溯到全部输入和规则版本。

## Stage 5：调仓、模拟账户与对账闭环

### 目标

完成正式计划审批、人工确认的成交/持仓文件导入、成交确认和策略账。

### 范围

- 实现调仓计划生命周期、版本和审批审计。
- 结合策略账和账户快照生成买卖建议，不调用下单接口。
- 实现受控 CSV/JSON 导入或人工录入，不连接券商 SDK。
- 实现幂等导入、待确认匹配、部分成交、多策略归属和人工确认。
- 实现策略账、实际/理论净值和总账/子账对账。
- 实现账户、信号、计划、交易和对账页面。
- 实现账户、运行和未关闭差异的风险门禁。

### 完成条件

- 一次完整流程可从正式模型预测走到计划、人工下单、同步、确认和对账。
- 系统不存在券商 SDK 或自动下单入口。
- 重复同步不产生重复成交或重复账务。
- 计划批准后不可原地修改；对账差异可追踪解决。
- 闭环以一个模拟账本、一个策略完成；多账户、多策略、成交拆分和未知外部交易由合成数据集成测试覆盖。

## Stage 6：模拟运行与系统验收

### 目标

用本地模拟账本和人工成交记录运行完整月度周期，证明系统具备个人使用条件。

### 范围

- 连续运行至少一个完整月度周期和不少于 4 次周度调仓。
- 记录数据更新、预测、计划、人工下单、成交、确认和对账证据。
- 演练程序重启、任务中断、数据源失败、部分成交、未成交、停牌和涨跌停。
- 执行本地/F 盘恢复演练和数据库迁移恢复演练。
- 复核日志、审计、风险阻断、模型有效期和运行手册。
- 形成独立验收报告和遗留问题清单。

### 完成条件

- 不存在无法解释的持仓或资金差异。
- 4 次调仓均有完整审计链和可复现输入。
- 故障恢复、风险阻断和备份恢复均有实际证据。
- 用户明确决定是否进入真实账户准备；系统不得自动切换。

## Stage 7：财务、估值、行业与指数成分

### 目标

在首期闭环稳定后扩展 point-in-time 基本面和结构化股票池数据。

### 范围

- 财务报表、公告日期和可用日期。
- 估值指标及来源口径。
- 行业分类及历史变更。
- 历史指数成分和权重。
- 基本面因子、行业约束和指数内选股实验。

### 前置条件

- Stage 6 完成。
- 数据来源、历史可用时间和修订处理有明确契约。
- 不允许只用当前行业或当前指数成分回填历史。

## 明确不在计划内

- 自动下单、自动撤单和无人值守实盘交易。
- 分钟/Tick、高频、盘口和低延迟架构。
- 融资融券、卖空和复杂衍生品。
- 多用户、云端托管、远程 API 和微服务。
- 没有独立批准的深度学习、强化学习和自动模型搜索。
