# 实施计划

本文定义阶段顺序、范围和完成条件，不记录逐次尝试或当前进度。当前阶段状态只在[路线图](ROADMAP.md)维护；具体合同和验收记录由各阶段目录承载。

## 执行规则

1. 每项工作声明所属 Stage，前一阶段未验收不得开始后一阶段。
2. 每阶段按领域纵向交付实现、入口、可观测性、测试和文档。
3. 已发布产物和已冻结证据不可原地修改；修订建立新版本。
4. 真实网络、运行数据根、旧项目读取和外部写入按任务单独授权。
5. 架构变更必须同时具备测试、验收证据和文档更新。

## Stage 0：工程与可恢复基线

目标是建立可重复开发、可审计持久化和可恢复运行的地基。

范围：

- Python/前端锁文件、固定工具链和离线质量门；
- 配置、密钥隔离、结构化日志与本地任务状态；
- SQLite 元数据迁移、备份恢复与失败注入；
- `127.0.0.1` Web 壳、健康检查和最小端到端测试；
- 旧项目只读清单与 REUSE/ADAPT/REWRITE/DISCARD/DATA_ONLY 分类。

完成条件：新环境可按文档启动；配置与敏感值不泄漏；迁移可重放；备份可恢复；完整离线门禁通过。

历史记录：[Stage 0](stage0/README.md)。

## Stage 1：日线数据仓与数据质量

目标是发布可查询、可追溯、失败关闭的 A 股未复权日线版本。

范围：

- BaoStock(A)、AKShare/腾讯(B)、AKShare/新浪(C) 独立适配器；
- Raw → Canonical → Resolution → Warehouse 不可变链路；
- schema、单位、交易日历、逐证券覆盖和多源一致性质量门；
- manifest 驱动的预算、血缘、原子发布、幂等复用与中断恢复；
- DataCenter 显式版本查询、来源投影和只读 verifier；
- EOD 命令、任务状态、日志、Web 投影和离线/集成测试。

完成条件：

- A/B 正常互验，C 仅在异常范围调用；至少两源一致才发布；
- 无法解释的缺口、分歧、schema 漂移或单源行稳定隔离；
- 已发布版本不可变且可由 manifest、Raw 批次和选源决定复算；
- 正式发布、只读复验、幂等路径和完整质量门均有验收记录。

冻结合同与历史记录：[Stage 1](stage1/README.md)。

## Stage 2：研究输入、因子与标签

目标是在同一显式父数据版本上，以最小范围建立可供 Stage 3 直接消费的 point-in-time 研究输入和可复现因子/标签，不在本阶段建设完整研究平台。

实施顺序：

1. 校准 BaoStock 架构门禁，冻结首次范围、研究参考来源资格与公司行动交接样例。
2. 修复并验收日常 EOD 显式日历入口，再按需扩展既有日线覆盖，发布 `ResearchInputVersion`。
3. 建立动态股票池、周度主标签和 10 个基础审计因子。
4. 构建可删除重建的 Qlib 全量视图，交付一个有界检查页并完成正式链终验。

完成条件：相同输入可复算；未来信息不能改变历史结果；退市证券不会因当前列表消失；缺失状态或复权冲突会隔离；因子和标签有版本、定义、输入血缘与单元测试；Qlib 可稳定消费同一显式版本。20 日对照标签、Alpha158、完整因子诊断和 Qlib 增量构建后移，不阻断 Stage 2 首次可用。

任务和验收入口：[Stage 2](stage2/README.md)。

## Stage 3：模型实验与审批

目标是从 Stage 2 显式研究版本训练可复算的简单基线，并批准一个可进入正式组合回测的候选模型。

实施顺序：

1. 冻结时间切分、20 日对照标签、实验 manifest 和数据/分数层指标。
2. 训练 Ridge 与 LightGBM，发布 `ExperimentRun`、模型 artifact 和 `PredictionSet`。
3. 运行一个 Alpha158 基准，交付最小模型检查页并由用户批准一个候选模型。

完成条件：实验可复算且无时间泄漏；模型只输出分数；候选模型、预测和输入血缘可复验；未经批准模型不能进入 Stage 4。Stage 3 不启用正式模型，不报告组合收益，不建设自动重训或通用审批平台。没有合格候选时保留工程检查和负面研究结论，Stage 3 记为待补充实验、未完成，Stage 4 不启动；后续实验作为另行授权的有界新任务/新 Job，不为关闭阶段降低批准标准或重写既有结果。任务和验收入口：[Stage 3](stage3/README.md)。

## Stage 4：组合、风险与双层回测

目标是把批准候选模型的分数转成唯一 `TargetPortfolio`，以最小共享规则完成 Qlib/Backtrader 双层回测，并在正式验收后启用模型。

实施顺序：

1. 实现固定 Top 30、5% 上限、3% 现金缓冲、成本/交易规则、最小公司行动处理和组合风险纯函数。
2. 让 Qlib 与 Backtrader 直接消费同一 `TargetPortfolio`，通过两个固定校准场景。
3. 完成一次有界正式回测、最小报告页和模型启用审计。

完成条件：两个引擎消费同一组合规则和成本假设；差异在阈值内或有解释；任何信号不直接生成订单。正式启用只发生在 Backtrader 验收通过后；不建设组合优化器、通用撮合或风险规则 DSL。任务和验收入口：[Stage 4](stage4/README.md)。

## Stage 5：调仓、模拟账户与对账

目标是用一个策略、一个本地模拟账本和一种规范文件格式形成人工确认的周度调仓闭环。本阶段完成即达到首次可监督使用里程碑。

实施顺序：

1. 从新增交易日重新构建研究输入，以既有启用模型推理，检查有效期/覆盖并结合账户快照生成计划。
2. 批准并导出计划，确认规范成交或最小公司行动调整，更新策略账并对账。
3. 交付一个调仓/账户工作区和包含新交易日刷新的一条完整 E2E，关闭一次模拟调仓闭环。

完成条件：模型→组合→风险→计划边界清晰；计划不可原地修改；系统不连接券商 SDK 或 QMT；成交必须由用户确认输入；首次使用流程可由用户在 Web/CLI 独立完成。不建设多券商格式或自动匹配引擎。任务和验收入口：[Stage 5](stage5/README.md)。

## Stage 6：模拟运行与系统验收

目标是在首次可监督使用基础上，以加速连续场景和一次实际人工流程验证恢复、操作手册和可接受性能。

实施顺序：

1. 回放四个连续历史周，覆盖重启、部分成交、重复导入、取消和失败恢复。
2. 复用既有备份/恢复与任务能力，完成一次人工 EOD/周度流程、模型健康复核、操作手册和系统终验。

完成条件：连续运行无血缘断裂；失败不产生半成品；新增模型/回测/计划/策略账可恢复；用户可按手册完成完整操作。不上内部调度器、外部告警平台或性能优化框架。任务和验收入口：[Stage 6](stage6/README.md)。

## Stage 7：扩展数据域

目标是在核心闭环稳定后，按实际研究或风险需求一次扩展一个财务、估值、行业或历史指数成分域。

实施顺序：

1. 选择一个有明确消费方的数据域，完成小范围来源资格与价值确认。
2. 复用现有数据版本和发布机制，发布一个有界数据版本。
3. 接入唯一首个消费方并完成该数据域验收；其他域继续保持未开始。

前置条件：Stage 6 通过。每个数据域必须重新完成来源、schema、point-in-time、质量、版本和血缘设计，不反向弱化既有质量门。Stage 7 不属于首次可监督使用或首期核心闭环的阻断项。任务和验收入口：[Stage 7](stage7/README.md)。

## 明确不在计划内

- 分钟/Tick、高频、融资融券、卖空；
- 自动模型搜索和深度学习；
- 多用户、远程开放 API 或微服务拆分；
- 券商 SDK、QMT 连接或自动下单；
- 未经单独合同与验收的数据域扩张。
