# S6-02 任务卡：人工运行、备份恢复与系统终验

状态：未开始、未授权。

## 目标与依赖

- Stage：6。
- 依赖：S6-01 已验收。
- 目标：由用户按手册完成一次真实操作路径，并验证新增业务事实可备份和恢复。

## 范围

- 形成最短操作手册：环境检查、启动、EOD、正式推理、周度计划、成交确认、对账、失败处理、
  备份恢复和安全关闭。
- 由用户从现有 Web/CLI 手动触发一次有界 EOD/周度流程；网络和正式写入在 dry-run 后单独授权。
- 总览只汇总现有数据新鲜度、使用中模型、最新计划、策略账、失败任务、风险阻断和待处理差异。
- 完成一次手动月度模型健康复核（审阅 R7）：绑定模型、预测、已成熟标签/评价版本，冻结观察
  窗口、最少样本、覆盖和衰减指标/阈值，记录 `INFO/WARNING/BLOCK`、原因与用户处置。
- 标签未成熟或样本不足记为无法评价并给出冻结的提示/阻断，不记作健康通过；不合并进推理特征。
  后续每次计划和批准检查最近显式复核记录及其有效期，复用 S5 风险入口；没有记录或记录过期的
  处置也进入冻结规则。用户手动决定是否建新实验，不自动重训、切换或发送外部告警。
- 把 SQLite、配置、模型、正式回测、计划、确认成交/公司行动调整、健康复核记录和策略账加入
  既有备份 manifest。
- 在隔离恢复目录执行真实恢复，检查迁移版本、SHA、版本引用、账务守恒和关键只读页面。
- 汇总 Stage 0～6 完整质量门与遗留限制，形成核心产品系统终验。

## 输出

- 用户操作手册、一次人工运行和模型健康复核记录、备份/恢复清单及隔离恢复证据。
- `docs/stage6/S6-02_ACCEPTANCE.md` Stage 6 与核心闭环终验记录。

## 测试与验收

- 用户无需开发工具知识即可按手册完成启动、运行、确认、对账和关闭。
- 失败路径提供明确下一步，不要求用户编辑数据库或任意本地文件。
- 健康复核覆盖表现衰减、样本不足/标签未成熟、复核缺失/过期；风险结论有独立预期，用户处置
  和复核版本可复验，不能因无法评价默认健康或自动替换模型。
- 恢复副本的关键版本、模型、回测、计划、成交和账务与备份 manifest 一致。
- 确认公司行动与健康复核在恢复后保持事件幂等、来源引用和审计完整；手册包含每月人工复核步骤。
- 完整离线质量门和关键端到端流程通过，实际外部授权与执行一致。

## 禁止项

- 不建设调度器、远程 API、邮件/短信、云端监控或自动恢复服务。
- 不在本任务启动 Stage 7 或扩展新数据域。
