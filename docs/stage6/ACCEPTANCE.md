# Stage 6 验收矩阵

状态：计划基线，未授权、未开始。全部项目通过并在 `S6-02_ACCEPTANCE.md` 记录实际证据后，
核心闭环完成系统验收。

## A. 四周连续业务

- [ ] 四个连续历史交易周使用同一策略账顺序完成 EOD、预测、计划、成交确认和对账。
- [ ] 每周输入和父版本显式，未来周数据不会改变之前已关闭计划或账务。
- [ ] 部分成交、取消/过期计划和下一周初始持仓衔接可解释。
- [ ] 重复 EOD、重复计划命令和重复成交导入均幂等。
- [ ] 至少一周贯通新交易日日线、研究全量构建、既有模型和新计划；复用依据同一输入指纹。

## B. 故障与恢复

- [ ] Worker 中断后运行中任务收束为 `INTERRUPTED`/失败，新 Job 可安全重跑。
- [ ] 发布或账务关键点故障不会产生半发布版本、重复成交或不平衡策略账。
- [ ] Web/Worker 重启后任务、模型、计划、成交、持仓、现金和差异状态一致。
- [ ] 失败目录、日志和输入清单保留，恢复不修改历史成功产物。

## C. 运行与性能

- [ ] 用户从现有 Web/CLI 手动完成一次实际 EOD 和周度流程，不依赖调度器。
- [ ] 总览/任务/日志能发现数据过期、模型不可用、失败任务、风险阻断和未关闭差异。
- [ ] 一次人工月度健康复核绑定模型/预测/已成熟评价输入和冻结指标，WARNING/BLOCK 有人工处置。
- [ ] 标签未成熟/样本不足不标健康通过；计划及批准读取最近显式复核，缺失/过期处置有负向样例。
- [ ] 单用户串行 EOD、推理、计划和回测的时间、内存和磁盘占用已记录且可接受。
- [ ] 未因未观察到的并行需求引入多 Worker、远程队列或扩缩容。

## D. 备份、手册与关闭

- [ ] SQLite、配置、模型、正式回测、计划、确认成交/公司行动调整、健康复核和策略账进入备份清单。
- [ ] 在隔离目录完成一次真实恢复，版本/SHA/账务守恒和关键只读流程通过。
- [ ] 用户手册覆盖启动、关闭、EOD、周度调仓、成交确认、对账、失败处理和恢复。
- [ ] 手册含每月手动健康复核及用户决定新实验的步骤，不依赖调度器或自动模型切换。
- [ ] 完整质量门、关键 E2E 和 Markdown 通过。
- [ ] `S6-02_ACCEPTANCE.md` 给出核心闭环完成结论；Stage 7 仍为按需扩展、未自动授权。
