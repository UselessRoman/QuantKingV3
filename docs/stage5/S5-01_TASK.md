# S5-01 任务卡：账户快照、正式预测、风险与调仓计划

状态：未开始、未授权。

## 目标与依赖

- Stage：5。
- 依赖：Stage 4 已完成且恰有一个 `使用中` 模型。
- 目标：从显式研究版本和账户快照生成可解释、可阻断、不可变的周度 `RebalancePlan`。

## 范围

- 定义一个规范 `BrokerSnapshot` CSV/人工录入 schema：账户标识、时点、现金、证券和持仓数量。
- 首个快照必须由用户明确确认后形成不可变策略账期初事件；后续外部快照只用于对账，不覆盖期初。
- 使用 `使用中` 模型对显式研究版本运行正式推理，发布仅含分数的 `PredictionSet`。
- 接通新交易日日线 → 复用 Stage 2 全量构建 → 新研究输入/股票池/因子 → 既有模型推理的应用链
  （审阅 R6）。显式传递父版本，只复用特征定义和训练时已拟合处理器，不复用过期矩阵或重新拟合。
- 校验特征定义版本、顺序、单位/复权口径及处理器与模型 manifest 兼容；最新信号日未来标签尚未
  成熟时仍可推理，推理路径不加载标签，也不能因标签尾部为空剔除合法信号日。
- 复用 Stage 4 组合服务生成 `TargetPortfolio`，不得在计划层重新选择 Top 30 或计算权重。
- 用账户净值、参考价、整手/零股和费用规则计算目标数量、买卖差额、预计费用和剩余现金。
- 风险扩展到数据/模型/规则/账户版本、资金、数量、停牌/涨跌停和计划有效期。
- 在同一风险入口冻结模型有效期、日历/时点判定和最低输入覆盖；模型过期或低于最低覆盖为
  `BLOCK`，不能把模型仍处于 `使用中` 当作有效性证据（审阅 R7）。月度人工表现复核由 S6-02 交付。
- 输出 `RebalancePlan` 草稿，绑定信号日、执行日、所有父版本、账户快照、目标持仓和风险结果。

## 输出

- `BrokerSnapshot`、正式推理用例、计划计算和账户级风险实现。
- 合成正式预测、`TargetPortfolio`、`RiskDecision` 和 `RebalancePlan` 链。
- `docs/stage5/S5-01_ACCEPTANCE.md` 实际验收记录。

## 测试与验收

- 非使用中模型、过期输入、版本不一致、资金不足和非法数量稳定阻断。
- 新日全链产出分数和计划，最新标签为空仍成功；特征定义/顺序/处理器不匹配、任一上游失败或
  未发布时阻止下游。全过程训练模型及已拟合处理器 SHA 不变，重复输入幂等。
- 模型过期、覆盖不足及有效期边界有独立预期测试；风险结果记录判定时点、阈值和输入版本。
- 数量为整数，买入按整手，零股只按冻结规则卖出，费用/现金使用 Decimal/定点语义。
- 相同输入计划内容幂等；更改账户快照、规则或模型产生新计划版本。
- 计划层不导入 Qlib/Backtrader，不调用券商，不直接修改策略账。

## 禁止项

- 不批准、导出或执行计划，不导入成交。
- 不建设多账户、多策略、券商格式或订单接口。
