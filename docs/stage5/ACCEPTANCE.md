# Stage 5 验收矩阵

状态：计划基线，未授权、未开始。全部项目通过并在 `S5-03_ACCEPTANCE.md` 记录实际证据后，
项目达到首次可监督使用。

## A. 正式预测、账户与计划

- [ ] 只有一个 `使用中` 模型可对显式研究版本生成正式 `PredictionSet`。
- [ ] 新日线经 Stage 2 全量构建得到新输入/因子后由既有模型推理；特征定义、顺序和处理器兼容，
  最新日未来标签为空仍可推理，训练 artifact 不变，上游失败/未发布阻断下游。
- [ ] 账户快照包含时点、现金和持仓数量，重复导入幂等；首次快照经用户确认形成策略账期初事件。
- [ ] 组合服务复用 Stage 4 唯一规则，计划层不重新选股或分配权重。
- [ ] 计划计算目标数量、买卖差额、参考价、预计费用和现金影响，数量/金额语义正确。
- [ ] 数据/模型/规则/账户版本不一致、资金不足和非法数量产生不可覆盖 `BLOCK`。
- [ ] 模型有效期/最低覆盖规则已冻结；模型过期或覆盖不足产生 `BLOCK`，判定时点和边界样例可复验。
- [ ] `RebalancePlan` 绑定全部父版本，批准后不可原地修改。

## B. 批准、导出与成交事实

- [ ] 用户能查看影响范围和风险后批准、取消或替换计划，所有动作有审计。
- [ ] 计划只导出规范人工执行文件，不包含券商 API 调用。
- [ ] 一个规范成交 CSV 和人工录入可生成只追加 `ImportedBrokerRecord`。
- [ ] 稳定成交 ID/复合键防止重复；精确匹配失败保持待确认，不自动写 `Fill`。
- [ ] 用户确认后才创建不可变 `Fill` 并更新策略账。

## C. 策略账与对账

- [ ] 现金、持仓、费用和权益由确认成交及确认公司行动调整确定性更新；非成交事件不伪造 `Fill`。
- [ ] 现金红利/送转复用 S4 独立手算样例；待确认不记账、跨文件重复及重复确认不重记，事实/来源/
  规则/确认审计可追溯；未解释的持仓事件阻断后续计划批准，不能通过覆盖快照消差。
- [ ] `BrokerSnapshot` 是外部总账快照，策略账是确认策略事实，两者不互相覆盖。
- [ ] 对账显示现金、持仓和未匹配差异及稳定原因；人工决定有审计。
- [ ] 重复成交、部分成交、零股、未匹配和取消计划固定样例通过。

## D. 首次可监督使用

- [ ] 一个调仓/账户工作区完成“生成→风险→批准→导出→导入→确认→对账”流程。
- [ ] Web/CLI 调用同一应用服务；命令幂等，API 不接受任意路径。
- [ ] 完整关键 E2E、后端/前端测试和质量门通过。
- [ ] 同一 E2E 从合成新交易日刷新贯通到既有模型、新计划和对账，并覆盖一笔人工公司行动调整；
  不以预建历史预测或只验证入队代替持续使用链。
- [ ] 用户可按简明步骤独立关闭一次模拟调仓，程序重启后事实仍存在。
- [ ] `S5-03_ACCEPTANCE.md` 明确记录首次可监督使用结论和限制。
- [ ] 阶段关闭只更新为“Stage 5 完成；已可监督使用；Stage 6 待授权”。
