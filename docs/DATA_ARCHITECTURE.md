# 数据架构与质量规范

## 目标

建立可替换、可校验、可追溯的本地 A 股日频数据仓。研究、回测、调仓和 Web 只能消费已发布数据版本，不能隐式读取供应商当前文件或“最新可用”目录。

## 数据范围

### Stage 1 必需数据

| 数据集 | 目的 | 关键历史语义 |
|---|---|---|
| 证券主数据 | 代码、名称、交易所、上市/退市和板块识别 | 必须保留历史状态，不只保存当前证券列表 |
| 交易日历 | 所有时间窗口、标签和执行日期 | 按交易所保存开闭市状态 |
| 未复权日线 | 因子基础、真实成交价和质量校验 | `open/high/low/close/volume/amount/pre_close` |
| 复权信息 | 构造连续研究序列 | 来源、算法和版本独立记录 |
| 交易状态 | 股票池和成交约束 | ST、停牌、涨跌停、上市/退市阶段 |
| 基准指数日线 | 收益对照和报告 | 指数行情不等于历史指数成分 |

底层保存全部沪深京 A 股历史，包括已退市、ST、长期停牌和上市初期证券。研究股票池在每个日期另行过滤。

### Stage 7 数据

- 财务报表及公告/可用日期。
- 估值指标。
- 行业分类及历史变化。
- 历史指数成分和权重。

Stage 7 数据进入研究前必须满足 point-in-time 可用性；只有报告期而没有公告或可用日期的数据不能用于历史因子。

## 数据源

| 来源 | 首期定位 | 限制 |
|---|---|---|
| XTQuant | 主数据源；行情、基础信息和交易状态 | 供应商对象不得越过适配器 |
| BaoStock | 核心日线和复权备用候选 | 必须通过覆盖、稳定性和口径实测 |
| AKShare | 补充与交叉校验候选 | 上游公开网站变化可能导致接口变化 |
| Tushare | 可选校验源 | 免费能力、频率和字段覆盖有限 |

Stage 1 使用固定证券和日期样本对候选源做基准测试，再确定正式备用矩阵。备用源不是“主源失败就自动接管”的开关。

## 数据分层

```text
Raw              供应商原始批次；来源隔离、不可变
    ↓
Canonical        统一代码、字段、单位和日期语义
    ↓
Research/Derived 复权视图、股票池、因子、标签、Qlib 数据
```

建议物理布局：

```text
E:\QuantKingV3Data\
  raw\<source>\<dataset>\<batch_id>\
  warehouse\<dataset>\<dataset_version>\
  qlib\<dataset_version>\
  artifacts\data-quality\<job_id>\
```

Raw 保存供应商原始字段或其无损表格表示、请求参数、抓取时间和响应摘要。Canonical 不保留供应商特有列名，来源信息进入清单和必要的血缘字段。

## 标准语义

- 内部证券代码使用 `000001.SZ`、`600000.SH`、`430047.BJ` 形式。
- 日期使用交易所本地交易日；持久化为明确的日期类型，API 使用 `YYYY-MM-DD`。
- 时间戳内部保存 UTC，Web 按 `Asia/Shanghai` 显示。
- 行情价格、成交量和成交额使用明确的数值类型和单位；供应商单位在标准化阶段转换。
- `volume` 的标准单位为股，`amount` 为人民币元。
- 未复权 OHLCV 永久保存；复权序列是派生数据，不得覆盖原值。
- 主键和排序由数据集契约定义；日线至少保证 `(code, trade_date)` 唯一。

详细字段在 Stage 1 通过可执行 schema 固化；文档不得替代 schema 和契约测试。

## 批次和版本

每次抓取产生 `IngestionBatch`，至少记录：

- `batch_id`、`source`、`dataset`。
- 请求参数、抓取开始/结束时间和适配器版本。
- 原始文件清单、大小、行数和 SHA-256。
- 供应商错误、重试和部分成功信息。

每次发布产生 `DatasetVersion`，至少记录：

- schema 版本及父数据版本。
- 输入批次和任何显式补洞记录。
- 覆盖日期、证券数、行数和分区清单。
- 质量规则版本、结果和差异报告。
- 生成代码版本、创建时间和发布状态。

研究任务必须显式引用 `dataset_version`。允许 UI 提供“选择最新已发布版本”的便利操作，但任务创建后必须解析并冻结具体版本。

Canonical Parquet 按数据集契约采用稳定分区；日线优先按交易年月组织，必要时再按证券代码桶细分。分区方案本身需要版本化，manifest 必须逐文件记录相对路径、分区键、大小、行数和 SHA-256，供发布、增量备份和恢复共同使用。

## 原子发布

```text
创建临时版本目录
    → 写入标准数据
    → 枚举实际文件
    → 运行质量检查
    → 写入 manifest
    → 比较 manifest 与实际文件
    → 原子重命名为已发布版本
```

失败目录标记为 `FAILED` 或保留不完整标识，写入结构化失败信息。不得修补失败目录后直接视为成功；修复必须创建新任务和新版本。

## 质量门禁

### 单源规则

1. Schema、类型、必填列和单位。
2. 主键唯一、排序稳定、证券代码可解析。
3. 日期属于交易日历，覆盖区间与请求一致。
4. `high >= max(open, close, low)`、`low <= min(open, close, high)`。
5. 价格、成交量和成交额非负；停牌等特殊值由契约明确。
6. 股票覆盖、最后交易日、连续缺口和异常空表。
7. 复权因子、除权日和未复权价格之间的连续性。
8. 证券历史状态与行情存在性的交叉检查。

### 跨源规则

- 仅在统一代码、交易日和单位后比较。
- 优先比较未复权 OHLC、成交量、成交额、交易日和复权事件。
- 差异阈值按字段定义，不能用单一百分比覆盖所有字段。
- 差异进入报告，包含证券、日期、字段、两侧值和口径说明。
- 超阈值差异阻止数据发布或将受影响分区隔离。

### 空结果

适配器必须区分“合法空数据”“无权限”“连接失败”“请求失败”和“解析失败”。禁止用空 DataFrame 表示成功。

## 备用源补洞

补洞只能通过显式 `SourceOverride`：

1. 主源缺口已经确认，不是停牌或合法无数据。
2. 备用数据通过字段和口径检查。
3. 记录来源、证券、日期范围、字段、原因和审批。
4. 发布新数据版本，不修改既有版本。
5. 下游 manifest 能显示使用了备用源。

## Qlib 导出

- Qlib 数据位于 `qlib\<dataset_version>`，是 Canonical 的可重建派生视图。
- 导出清单记录源数据版本、字段、复权规则、日历、证券范围和导出代码版本。
- Qlib 自带公共数据不得替代 QuantKing 的 XTQuant 标准数据。
- 删除 Qlib 派生目录后应能从 Canonical 重建，不影响主数据血缘。
- 已发布 Qlib 目录不可原地追加、修补或覆盖。
- 只有父数据版本兼容且变更是可证明的追加交易日或新增证券时，才允许把父 Qlib 视图复制或克隆到新临时目录后增量导出；历史修订、schema/复权/日历变化必须全量重建。
- 增量导出必须验证文件清单、日历、证券区间和抽样值，并按 Stage 2 固化的频率与全量重建结果校准；任何不一致都回退为新的全量构建任务。

## 更新流程

日常收盘后流程由用户从 Web 或 CLI 手动触发，两种入口调用同一应用服务。首期不建设内部调度器或 Windows 任务计划。

```text
交易日确认 → XTQuant 增量抓取 → Raw 落地 → 标准化
    → 质量检查/备用源抽样 → 发布 DatasetVersion
    → 派生 Qlib 数据 → 因子/预测/信号任务
```

只有数据版本成功发布后，后续任务才可启动。任何数据源或质量失败必须在总览和数据中心显示，并阻止正式信号。
