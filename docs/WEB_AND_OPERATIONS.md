# Web、任务、日志与运维

## Web 技术栈

- FastAPI：同源 API、输入输出 schema、SSE 和静态前端托管。
- React + TypeScript：状态密集的研究、审批和对账界面。
- Vite：开发与生产构建。
- Apache ECharts：K 线、净值、回撤、因子和散点图。

生产使用时由一个本地启动入口启动 Web 和工作进程，并打开 `http://127.0.0.1:<port>`。Node.js 只用于前端开发和构建，不要求最终用户单独启动 Node 服务。

## 页面结构

| 页面 | 核心内容 |
|---|---|
| 总览 | 数据新鲜度、当前模型、最新信号、模拟账户、待办、任务和风险告警 |
| 数据中心 | 来源、批次、数据版本、覆盖、质量和跨源差异 |
| 因子研究 | 定义、版本、覆盖、分布、IC、分组收益和相关性 |
| 模型实验 | 配置、训练、指标比较、产物、审批、启用和停用 |
| 回测中心 | Qlib/Backtrader、净值、回撤、交易、成本和结果对比 |
| 信号与调仓 | 分数、目标组合、计划、预计费用、风险、批准和取消 |
| 交易与对账 | QMT 账户、委托、成交、待确认匹配、策略账和差异 |
| 任务与日志 | 进度、实时日志、失败、取消和产物 |
| 系统设置 | 路径、QMT、费用、策略、日志和运行环境检查 |

## API 边界

- 路由只做验证、授权边界（本机）、用例调用和响应映射。
- 业务对象与 API schema 分离，避免 Web 字段成为领域模型。
- Web 不直接访问 Parquet、SQLite、日志文件或 XTQuant。
- 批量行情由后端分页、聚合或降采样，禁止向浏览器返回全市场原始表。
- 写操作采用命令式端点并返回资源/任务 ID；重试必须幂等。
- 同源访问，不启用开放 CORS；默认不建设登录和多用户权限。

## 后台任务

任务状态至少包括：

```text
PENDING → RUNNING → SUCCEEDED
              ├─ FAILED
              └─ CANCELLED
```

被程序重启中断的运行中任务必须在恢复时标记为 `INTERRUPTED` 或等价失败状态，不能继续显示为运行中。

每个 `JobRun` 保存：

- 任务类型、输入版本、配置版本和请求者。
- 创建、开始、结束和心跳时间。
- 当前阶段、完成量和进度说明。
- 工作进程标识、日志路径和产物路径。
- 成功清单或结构化失败信息。
- 取消请求、取消结果和不可取消阶段。

数据写入、QMT 访问和版本发布任务串行执行。训练和回测首期默认各只运行一个，后续根据资源测量再开放并行。

Worker 还写入低频 `JobEvent`：

- 使用单调递增 `event_id`，记录任务、事件类型、阶段、进度、摘要和时间。
- 状态变更与对应任务事件必须在同一短事务提交，保证断线恢复时不会看到无法解释的进度。
- 心跳和重复进度需要合并或限频；完整日志行不得写入事件表。
- Web 只读查询 `event_id > cursor` 的有界批次，不把 SQLite 当成高吞吐消息队列。

## 进度与取消

- Web 轮询 SQLite `JobEvent`，再使用 SSE 向浏览器发送单向进度事件；浏览器通过 `Last-Event-ID` 或等价游标恢复。
- 完整任务日志保存在 JSON Lines，由受控日志读取服务按文件标识和字节偏移尾随；SSE 可以推送日志尾部，但 SQLite 只保存索引和摘要。
- REST 任务状态和日志尾部轮询作为降级路径。
- 取消是协作式的：任务在安全检查点响应，不在数据库提交或原子发布中间强杀。
- 取消任务保留输入、日志和未发布临时产物，并明确标记。

## EOD 触发

- 首期由用户从 Web 或 CLI 手动启动 EOD 流程，两种入口调用同一应用服务并产生相同的幂等任务。
- 不建设内部调度器，也不依赖 Windows 任务计划。
- 重复点击或重复命令不得创建相同输入版本的重复发布；运行中的同类任务必须明确拒绝或返回已有任务。

## 结构化日志

### 类型

1. 运行日志：Web、Worker、数据库和 QMT 连接。
2. 任务日志：数据、因子、训练、回测、同步和备份。
3. 业务审计：模型/计划审批、成交确认、风险覆盖和配置变更。
4. 质量与验收报告：正式产物，不混入普通日志。

### 字段

每条结构化日志可包含：

```text
timestamp, level, event, message, module,
process, task_id, run_id, data_version,
model_version, plan_id, duration_ms, exception
```

时间保存 UTC，Web 使用 `Asia/Shanghai` 展示。账户标识使用掩码；密码、令牌和完整敏感配置禁止进入日志。

### 存储和保留

- 控制台输出用于开发和诊断。
- 完整运行/任务日志使用轮转 JSON Lines 文件。
- 每个任务有可定位的独立日志流。
- SQLite 保存索引、错误计数、摘要和业务审计，不保存全部高频日志。
- 普通日志默认保留 90 天，旧日志可压缩后清理。
- 审计记录、失败验收报告和正式产物不自动删除。
- 单模块 `DEBUG` 可临时启用并设置自动恢复时间。

### Web 日志能力

- 实时尾随、暂停、关键词搜索和级别过滤。
- 按任务、模块、时间和关联业务 ID 查询。
- 完整异常堆栈和关联产物跳转。
- 全局 `WARNING/ERROR/CRITICAL` 视图和重复次数。
- 业务审计独立标签页。
- 导出任务日志，但不暴露任意本地路径。

## 配置版本

配置分三类：

- 默认配置：入 Git，无机密。
- 本机配置：路径、账户和环境，不入 Git。
- 业务配置版本：因子、模型、组合、费用和风险参数，保存在 SQLite 并可审计。

Web 修改业务参数时创建新版本；已经被实验、回测或计划引用的版本不可修改。

## 健康检查

系统设置和总览应显示：

- Python、锁文件和数据库迁移版本。
- 数据/备份目录是否可写及剩余空间。
- XTQuant/QMT 是否可连接以及最近成功时间。
- Worker 心跳和队列积压。
- 最新数据、因子、模型和账户快照时间。
- 最近失败任务、未关闭对账差异和风险阻断。

## 备份

### 本地恢复快照

`E:\QuantKingV3Data\backups` 用于升级、数据库迁移和发布前恢复，至少保护 SQLite、配置、清单和关键产物。

### 异盘灾难备份

`F:\QuantKingV3Backups` 防止 E 盘损坏，优先保存：

- SQLite 一致性备份和迁移版本。
- 本机配置的安全副本与数据版本清单。
- 人工确认成交、策略账和对账记录。
- 已批准模型、正式回测、调仓和验收报告。

Raw 和 Warehouse 可按容量采用较低频率增量备份，但必须记录哪些数据可重建、从何重建。增量备份由源数据 manifest 和 SHA-256 驱动，只复制目标端缺失或校验和变化的分区对象。

### 备份约束

- SQLite 使用在线一致性备份，不复制正在写入的单个主文件冒充成功备份。
- 每个备份有清单、校验和、代码/数据库版本和完成标记。
- 不完整备份不得发布为恢复点。
- 备份复制过程不得使用会隐式删除历史版本、失败产物或既有恢复点的镜像删除语义；保留清理由独立、可审计任务执行。
- Stage 0 通过 Windows 与 F 盘实测选择具体工具，并固化频率、保留期、加密/访问控制和恢复演练步骤。
- 只有实际恢复并通过校验的备份才可标记为“已验证”。

## 启动和关闭

- 启动前检查目录、数据库迁移、锁文件、端口和单实例锁。
- 同一数据根目录首期只允许一个写入实例。
- 关闭时停止接收新任务，等待安全检查点，提交日志并关闭数据库连接。
- 强制中断后的首次启动执行任务和临时目录恢复检查。
