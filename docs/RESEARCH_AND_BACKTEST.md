# 因子、模型、组合与回测

## 原则

研究结果必须可复现、可解释输入来源，并与实际执行时序一致。Qlib 是研究执行引擎，不拥有 QuantKing 的数据、因子、标签、股票池或组合语义。

## 研究主链路

```text
DatasetVersion + 股票池规则版本
    → Qlib 派生数据
    → 因子集版本
    → 标签版本
    → 训练/验证/测试时间切分
    → 模型训练与预测
    → 因子/模型评价
    → PredictionSet
    → TargetPortfolio
    → Qlib 快速回测 / Backtrader 正式回测
```

## 动态股票池

底层数据全量保留，模型在每个历史日期应用当时已知的过滤条件：

- 已经上市且尚未退市。
- 上市满 120 个交易日；该值作为首期默认，允许版本化实验调整。
- 当日未停牌。
- 不属于 ST、`*ST` 或退市整理期。
- 满足历史窗口和必要字段覆盖。
- 通过流动性过滤；具体窗口和分位阈值在 Stage 2 固化。

过滤必须使用历史状态，不得把当前名称、当前状态或当前上市列表回填过去。历史指数成分进入 Stage 7 前，不得宣称首期策略是某指数历史成分内选股。

## 因子注册

每个 `FactorDefinition` 至少声明：

- 稳定 ID、名称、版本和说明。
- Qlib 表达式或受管理 Python 实现。
- 输入字段、复权口径和最大回看窗口。
- 数据可用时间和延迟规则。
- 缺失值、异常值、去极值、标准化和方向。
- 输出频率和所属因子集合。
- 测试样本和人工核对方法。

同一因子区分：

1. 原始因子值。
2. 去极值、标准化或截面排序后的处理值。
3. 某实验实际使用的模型特征及顺序。

修改预处理即产生新因子集版本，不能只修改配置后沿用旧版本号。

## 首期因子集

### 基础审计集

10～20 个易于人工核对的技术因子，覆盖：

- 短中期动量与反转。
- 收益和价格波动率。
- 均线或价格位置。
- 成交量变化与量价关系。
- 换手或成交额流动性代理。

每个因子先在小型确定性样本中验证，再运行全市场。

### Alpha158 基准集

Qlib Alpha158 作为标准基准，用于验证 Qlib 数据和模型管线，并与基础审计集比较。它不是默认生产因子集，也不能绕过因子注册和版本记录。

## 标签

- 主标签：与实际持有区间对齐的未来 5 个交易日收益，对应周度调仓。原则上从 T+1 执行参考价开始，到下一周度调仓执行参考价结束。
- 对照标签：未来 20 个交易日收益。
- Stage 2 必须用具体交易日历样例固定精确下标、执行参考价、节假日、停牌、涨跌停和无法成交处理，不能直接把“T+1 开盘到 T+5 收盘”当成默认公式。
- close-to-close 收益可以作为研究对照，但不能替代执行对齐主标签。
- 标签只用于训练和评价，永远不能进入特征。
- 标签窗口不得跨越训练、验证或测试边界造成泄漏。
- 性质测试必须证明：修改 T 之后的数据不会改变 T 及以前的特征和股票池；修改声明标签终点之后的数据不会改变该标签；推理路径不加载标签。

## 时间切分

- 禁止随机拆分时间序列。
- 训练、验证和测试按交易日期严格分离。
- 默认使用滚动或走步验证，保存每个窗口的日期和输入版本。
- 标准化、去极值参数和任何可学习预处理只能在训练区间拟合。
- 重叠标签需要使用隔离窗口或等价防泄漏措施。

## 模型基线

| 模型 | 目的 |
|---|---|
| 线性/Ridge | 检查标签方向、特征尺度和线性基线 |
| LightGBM | 首期正式非线性基线 |
| 复杂模型 | 仅在前述基线稳定后另行决策 |

首期不建设 LSTM、Transformer、强化学习、自动因子挖掘或自动模型上线。

## 实验与模型清单

每个 `ExperimentRun` 保存：

- 数据、股票池、因子集和标签版本。
- 训练、验证、测试日期段。
- 处理器、特征顺序、参数和随机种子。
- Python、Qlib、模型库和代码版本。
- IC、Rank IC、ICIR、覆盖率和分期稳定性。
- 模型文件、预测、特征重要性、日志和 SHA-256。

模型状态：

```text
草稿 → 已训练 → 已验证 → 已批准 → 使用中 → 已停用
          └─ 验证失败
```

只有 `使用中` 模型能生成正式调仓计划。模型启用、替换和停用必须写审计记录。

该生命周期在 Stage 3 启动时根据单用户实际用例复核；本次 Stage 1 简化不提前改变 ADR-012，也不提前实现审批状态机。

## 模型复核与重训

- 首期不自动重训，也不允许风险告警自动替换使用中模型。
- 每月执行一次模型健康复核；每次生成正式计划时仍检查模型有效期、输入覆盖和近期表现衰减。
- 过期或衰减只产生 `WARNING` 或按规则产生 `BLOCK`，由用户决定是否手动创建新的 `ExperimentRun`。
- 新模型必须重新完成训练、验证、批准和启用；不得覆盖或原地更新使用中模型。

## 模型评价

不能只看累计收益。至少报告：

- IC、Rank IC、ICIR 及年度/滚动稳定性。
- 因子覆盖、缺失、分布和相关性。
- Top-N 收益、超额收益、最大回撤和风险调整收益。
- 换手率、成本敏感性和持仓集中度。
- 不同市场区间、证券规模和流动性分组表现。
- 与线性/Ridge 和简单排序基线的增益。

## 组合构建

模型只输出 `PredictionSet`：`signal_date × code → score`。QuantKing 组合服务负责：

1. 应用动态股票池和可交易过滤。
2. 选取分数最高的 30 只股票。
3. 生成基本等权目标。
4. 应用 5% 单股上限和 3% 现金缓冲。
5. 应用换仓缓冲、流动性和换手规则。
6. 输出不可变 `TargetPortfolio`。

行业约束在 Stage 7 获得可靠行业数据后加入。首期不使用缺乏历史语义的当前行业分类回填。

## 双层回测

本节仍是 Stage 4 的当前目标，但不在 Stage 1 提前扩展实现。Stage 4 启动时必须先以实际组合和回测需求复核双引擎校准成本；在新的 ADR 生效前，既不删除已验证的 Qlib `TargetPortfolio` 接口，也不新增第二套组合逻辑。

### Qlib 快速回测

用于模型筛选、信号分析、参数敏感性和快速对比。允许采用简化成交假设，但必须显式记录。

QuantKing 自定义 Qlib Strategy 适配器必须按日期直接返回组合服务已经生成的 `TargetPortfolio` 目标权重。它不得根据预测分数重新执行 Top-N、换仓或权重分配；Qlib 内置 `TopkDropoutStrategy` 等组合构造策略不得用于正式候选策略或双引擎校准。

### Backtrader 正式回测

用于候选策略正式验收，至少覆盖：

- T 日收盘出信号、T+1 开盘执行。
- 账户现金、持仓和先卖后买。
- T+1 可卖限制。
- 买入整手与零股卖出。
- 停牌、涨跌停和不可成交。
- 佣金、最低佣金、印花税、其他费用和滑点。
- 订单占成交量比例、部分成交或保守拒单。
- 交易所、板块和历史日期对应的规则版本。

Backtrader 适配器只执行 `TargetPortfolio` 或调仓订单建议，不能重新实现选股和目标权重逻辑。

## 双引擎校准

校准分为两级：

1. 基础场景：完全可成交、相同价格和费用为零，比较目标持仓、成交方向、现金和净值。
2. 共同规则场景：使用同一版本的佣金、最低佣金、印花税等成本，覆盖整手、停牌、方向性涨跌停和资金约束，比较订单、成交、拒绝、现金、持仓和净值。

两级均需达到预定容差或有固定测试说明。对于 Qlib 无法表达而 Backtrader 正式回测必须覆盖的精细规则，先验证共享交易规则内核的决定，再记录引擎差异；不能为了追求表面一致而降低 Backtrader 口径，也不能选择表现较好的一侧作为结论。

## 回测产物

正式回测至少保存：

- 输入版本和执行规则版本。
- 每期分数、目标持仓和调仓计划。
- 订单、成交、拒绝和未成交原因。
- 日度现金、持仓、净值和基准。
- 收益、回撤、换手、成本、集中度和分阶段指标。
- 完整日志、清单和校验和。

失败回测不得覆盖成功结果，也不得进入模型审批。
