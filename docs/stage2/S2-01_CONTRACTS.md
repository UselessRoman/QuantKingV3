# S2-01 研究合同 v1

Stage 2 / S2-01 的离线合同。来源资格和正式范围尚未通过，不能据此启动 S2-02 或发布研究产物。
可执行对象见 [contracts.py](../../src/quantking/research/contracts.py)，配置见
[research_rules.v1.json](../../configs/research_rules.v1.json)。本任务不新增发布器、状态机、数据库表。

## 时间、主键与缺失

内部时间使用 `UtcTimestamp`，交易日期使用交易所本地 `date`；收盘知识截止为交易日
15:00 Asia/Shanghai（07:00 UTC）。收盘后才披露的事实不用于当日信号。`available_at` 是有
证据支持的安全消费起点，`observed_at` 是采集观察时间；后者不能反推前者。历史采集可以晚于
历史可用时间，但必须保存当时披露/状态生效的证据；无法证明时不得回填。

按 [ADR-031](../DECISIONS.md)，`SourceFact.precision` 为 EXACT 或 DATE：EXACT 保留既有精确
时间；DATE 必须绑定 `PublicationDateEvidence`（公告标识、修订、文档 SHA、官方发布日期及
发布记录 SHA），由 `from_publication_date()` 计算 D+1 自然日 00:00 上海的保守可用边界。
例如 2023-06-07 发布对应 `2023-06-07T16:00:00Z`；D 收盘拒绝，恰到该边界允许知识时间检查。
周五发布的边界为周六零点，不依赖交易日历。直接构造 DATE 时也必须等于所算边界。

发布日期记录必须事先通过来源资格并绑定当前文档/修订。schema 检查修订和文档 SHA 一致、
引用非空及时间边界，不能自动证明记录的权威性或文件字节。正文落款、URL 日期、搜索摘要不能
单独形成 DATE 资格；新修订不得复用旧文档发布证据。精度混填、绑定不符和观察早于安全边界拒绝。

每行绑定 `source/revision/evidence_sha256/available_at/observed_at/precision` 及适用的日期证据。修订形成新父版本和
新研究版本，不更新已发布行。构建时先按显式版本选定来源修订，再进行主键唯一性与覆盖检查。
同键重复、不同来源冲突、空集、未来可用信息均拒绝；不能默默取最后一条。

| 数据集 | Canonical 主键 | 字段与语义 | 缺失策略 |
|---|---|---|---|
| security_lifecycle | code，所选修订内一条 | listed_on 含当天；delisted_on 是首个不再上市日期，区间右开 | 无行/首次上市日不明阻断；null 结束日期仅表示证据时点已知未终止，不代表永不退市 |
| security_status_daily | code, trade_date | risk_status= NORMAL/ST/STAR_ST/DELISTING；suspended 为明确布尔 | 任一未知隔离，不从名称或交易量猜测；不能把 isST=1 自动区分 ST 与 *ST |
| adjustment_factor_daily | code, trade_date | anchor_date 不晚于该日；cumulative_factor 是正有限 Decimal，无量纲 | 因子为空、零、负数、NaN、未来锚点、未知事件覆盖阻断 |

`validate_reference_rows` 检查结构、知识时间、重复键和同证券锚点一致；锚点当日因子必须归一为 1。
它不检查证券/日期完整覆盖。
S2-02 必须基于冻结交易日历、生命周期与显式父版本补充逐键覆盖，校验生效日期不晚于消费日。
上市前和退市后的合法无行需要生命周期证据；窗口内停牌仍需显式状态，不等于可忽略的缺行。

## 研究价与公司行动

研究价格为 `unadjusted_price[t] * F[t] / F[anchor]`。锚点固定在每只证券取数窗口首个合格日，
归一为 1；仅累乘截至 t 已生效且在知识截止前可知的事件比例。晚于 t 的公司行动不得改变 t
及之前价格，禁止用“最新一天”归一。供应商前/后复权因子的方向和事件比例必须资格验证后映射；
不能将未经证明的供应商累计值直接认定为 F。volume 保持股、amount 保持 CNY，不随研究价复权。

连续研究价用于特征/标签；未复权价用于成交和估值；交易规则参考价另行取证。`pre_close`
不能默认充当除权参考价。累计因子不能推导每股现金、送转股数、到账日或税费。

公司行动键为稳定 `event_id + source.revision`，包含证券、CASH_DIVIDEND/BONUS_SHARES、
披露时间、可用时间、登记日、除权日、每股现金（CNY/原股）或每原股新增股数、现金到账日或
新增股可卖日、除权参考价（CNY/股）、税费口径及证据引用。复合事件用两个明确关联的事件键，
不得一行混用单位。执行缺字段由 `execution_gaps()` 列出；任何持仓跨事件的正式回测在相关
字段不足时阻断。Stage 4 才实现持仓、应收和现金，不在此执行记账。

公司行动 EXACT 分支保留 `disclosed_at` 且 `disclosed_on=null`；DATE 分支必须
`disclosed_at=null`、`disclosed_on=source.publication.published_on`。精确时间和日期不能混填；
安全消费边界不得写入实际披露时刻。日期精度不消除现金支付、可卖日或税费等执行缺口。

## 股票池与流动性

证券集合先取窗口内曾上市证券，再逐历史日过滤。上市交易日龄为所属交易所日历中
`listed_on <= session <= T` 的开市日数量，**第 120 日可纳入，第 119 日排除**；停牌日计入
上市交易日龄，不以实际行情行数代替日历。未上市、已退市、ST、*ST、退市整理、停牌、未知
状态、必要窗口不足、低流动性分别保留原因，多个原因同时保留。

流动性窗口为包括 T 的最近 20 个交易日，要求 20 个可靠成交额观测。已确认停牌且来源明确
提供成交额 0 时该 0 参与窗口；缺行不能填 0。中位数为排序后第 10/11 项均值，门槛
`>= 10,000,000 CNY`。不足 20 日或任一未知隔离。基础因子的额外回看缺口由其定义单列。

固定样例 10 个 900 万和 10 个 1100 万，中位数恰好 1000 万，纳入。
备选横截面规则“按中位数排序，剔除最低 ceil(20% * N)，同值以代码排序”：原截面
900/1000/1100/1200/1300 万时剔除 900；增加四个 100 万证券后 N=9，只剔除两个 100，
原先的 900 变为通过。首版选择绝对阈值以避免证券集合覆盖变化直接改变同一证券资格。
规则配置版本冻结上述选择；修改门槛或窗口需新版本，不把本规则称为换手率。

## 周度信号、标签与成交假设

信号日为固定完整交易日历中 ISO 年/周的最后一个开市日；不得用截断行情的最后一行猜测周末。
取数/预热日与信号日分开。对信号 s_k，入场索引为 `calendar.index(s_k)+1`，出场索引为
`calendar.index(s_(k+1))+1`；标签为两端连续研究 open 之比减 1。通常持有 5 个交易日，
节假日周按真实日历可缩短；不得强制改成 T+5 收盘。

端点缺行、停牌、生命周期外或方向性不可成交时标签为空并记录原因；买入端一字涨停阻断，
卖出端一字跌停阻断。不顺延、不前填。只有已知该证券该日交易规则限价且 OHLC 全等于限价
时才据日线作方向性保守拒绝；普通触及限价不能证明全天不能成交，保留开盘执行假设标志。
交易规则/参考价不明单列 `EXECUTION_RULE_UNKNOWN`，不假设普通开盘可成交。标签未来端点
不参与 T 的股票池/特征，标签可用时间为两个端点事实均已可用之后；切分必须容纳实际终点。

## 通用 artifact manifest

五类逻辑产物共享 `research-artifact-manifest.v1`，分别保留独立 `research_version` ID：
ResearchInputVersion、UniverseVersion、LabelVersion、FactorSetVersion、QlibViewVersion。
父引用为显式版本 ID + manifest SHA；ResearchInput 必须包含 Stage 1 data_version 父引用。
构造 schema 不能证明父状态，S2-02 发布入口必须读取并验证父 `PUBLISHED` 和实际覆盖，拒绝
`latest`、可变路径及仅凭 ID 推断资格。

范围含排序去重证券、实际取数交易日集合、信号起止、日历版本、集合来源证据 SHA。
规则摘要为规则配置指纹，内容 SHA 对排序文件清单（路径、大小、文件 SHA）作规范 JSON SHA。
完整指纹另绑定 artifact_type、版本 ID、父引用、范围 SHA、规则 SHA、代码版本、依赖锁 SHA、
排序缺口。规范 JSON 使用 UTF-8、键排序、无空格分隔符；数值规则使用规范 Decimal 文本。
相同文件重建的内容 SHA 相同，版本/代码/缺口变化使完整指纹不同。
代码版本在脏工作树中必须绑定实际源码快照摘要，不能只记录未包含当前修改的 HEAD；
依赖版本使用实际锁文件 SHA，不使用当前环境名称代替。

文件项复用既有 `ManifestFileEntry`，发布复用现有 Job、manifest、文件集合校验与原子发布。
本任务仅验证 payload，不实现文件发布，不宣称已验证实际文件 SHA 或生产父版本当前状态。
