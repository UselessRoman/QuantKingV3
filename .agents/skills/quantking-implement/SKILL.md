# QuantKing 编码交付

读取根 [AGENTS.md](../../../AGENTS.md)、[路线图](../../../docs/ROADMAP.md)、当前任务卡和
[技术标准](../../../docs/TECHNICAL_STANDARDS.md)；涉及语义变化时查 [决策](../../../docs/DECISIONS.md)
及相关领域合同。根规则中的阶段、外部授权、工具链和不可变产物要求持续适用。

## 从验收条件开始

确认本次 Stage、目标行为、变更边界和已有授权。用 `scripts/git-read.ps1` 检查分支与工作树，
识别用户原有改动；用 `rg` 找实际入口、调用者、数据契约和最近的相关测试，再读必要实现。
不要因为看到待办、历史缺陷或后续阶段目录就顺手实施。

把任务卡接受条件映射到可观察行为和检查方式。复杂任务维护简短计划；简单修复直接进入复现。
遇到同类失败先缩小样例、定位原因，不重复运行同一无效命令。

## 复现、实现、贯通

- 缺陷先取得最小复现；任务要求测试先行时先运行有意义的失败测试。涉及业务和数据的预期来自
  独立手算、冻结合同或固定样例，不能调用实现生成期望值。纯文案/格式不添加镜像测试。
- 先实现最小业务闭环，再接通本任务要求的适配器、应用入口、API、Web、日志和错误反馈。
  阶段纵向交付按任务卡分配，不为每个底层模块添加页面。
- 沿现有代码模式修改；领域边界使用类型和稳定错误，不泄露第三方对象。语义变更先更新已获
  授权的合同文档，重大未决产品选择交由用户决定，局部可逆选择自主完成。
- 与当前修改相关时，覆盖缺失/冲突、边界时间、重复请求和部分失败。拒绝必须发生在不允许的
  发布或外部副作用之前；不能靠空结果、吞异常或默认“最新”掩盖失败。
- 能独立分配的文件交给子代理；共享契约和集成由主代理负责。收到中途纠正时仅调整失效部分，
  保留仍有效的实现和已验证证据。

## 使用固定工具链验证

从仓库根使用 `scripts/uv.ps1`、`scripts/npm.ps1`，或点调用
`scripts/activate-toolchain.ps1` 后使用其导出的可执行路径。Python 定向执行保持
`run --offline --frozen`；共享缓存不可写时用激活脚本的 `-UvCacheDirectory .uv-cache`。
具体测试路径与参数从现有配置确认，离线 pytest 排除项以 `scripts/quality.ps1` 当前 marker
表达式为准，不能用未过滤的全测试调用意外触发真实资源。

先运行受影响的测试；跨模块变化增加相关契约/集成检查，用户流程变化验证实际 API/Web 链路。
完整门禁仅使用：

```powershell
.\scripts\quality.ps1 -UvCacheDirectory .uv-cache
```

提交前、正式验收或任务卡要求时运行完整门禁；开发中的定向检查不替代它。通过后只有新增修改、
失败或未决疑点才扩大或重跑。环境权限/缓存问题要单列，不擅自联网补包，也不写成测试断言失败。

## 交付与复核

重要行为变化安排独立只读审查，提供原始目标、候选差异、测试和证据路径；主代理核验具体发现，
修复后重跑受影响检查。审查无法独立完成时如实标注自查。

同步本任务需要的合同、实施/验收记录与能力说明。报告本次改动、命令及结果、未执行项和阻断，
避免把工作树其他修改归到本次成果。未获授权不提交 Git 元数据或启动后续任务；取得提交授权后
通过沙箱升级机制执行，不用直接写 `.git` 绕过权限。

正式运行失败时保留原目录、日志、输入清单和失败状态。仅在已授权范围内诊断及离线修复；
重跑必须是新任务/attempt，并按根规则核实新授权。不得把失败产物补成成功。
